1. How Angular works

Angular is a TypeScript-based frontend framework for building client applications. Modern Angular applications generally use standalone components, a router for client-side navigation, dependency injection for services, and reactive state via signals or RxJS Observables.

ElementResponsibility
BrowserLoads HTML, CSS, and JavaScript; executes Angular application code.
ComponentOwns a view, template, styles and UI behavior.
ServiceEncapsulates shared concerns, such as data retrieval or application state.
RouterConnects URLs to views without requiring a full page reload.
Spring Boot APIProvides server-side business logic, authorization and persistent data; never trust browser-side authorization alone.
Angular is not a replacement for Spring Boot. In this bootcamp, Angular acts as a browser client for protected REST APIs.

2. Prerequisites and installation

Install a currently supported Node.js LTS release supported by your chosen Angular version, along with npm, VS Code, and Git. Angular/Node version compatibility changes by release; check the official compatibility table before installation.

Official references: Angular version compatibility, Node.js downloads, and Angular CLI setup.

macOS (Terminal)

node --version
npm --version
npm install -g @angular/cli
ng version

Install Node.js using the official installer or your preferred version manager. On Apple Silicon, use ARM64-compatible tooling. Avoid using sudo npm install -g; use a correctly configured Node version manager if permissions fail.

Windows (PowerShell)

node --version
npm --version
npm install -g @angular/cli
ng version

Install Node.js from its official Windows installer, then reopen PowerShell. If PowerShell blocks the npm.ps1 shim, use npm.cmd or adjust execution policy according to your organization's security policies.

Linux (Ubuntu/Debian/Fedora)

node --version
npm --version
npm install -g @angular/cli
ng version

Install a compatible LTS version of Node.js via an approved version manager or vendor repository; distribution default packages may be too old for recent Angular CLI releases.

3. Create and run your first project

Use the Angular CLI to create a standalone application. Accept the prompts appropriate to your local version; CLI defaults may evolve.

ng new internship-orders --routing --style=css
cd internship-orders
ng serve --open

The development server normally uses http://localhost:4200. Keep it for local learning only; production deployments use a built application served by a web server or hosting platform.

ng generate component features/orders
ng generate service core/orders

Explore src/app, inspect the generated component, and locate the route configuration. Use ng build to verify an optimized build.

4. TypeScript fundamentals for Java developers

TypeScript checks types during development, but browser JavaScript does not enforce interfaces at runtime. Treat network responses as untrusted inputs.

export interface Order {
  id: number;
  customerName: string;
  total: number;
  status: 'NEW' | 'PAID' | 'CANCELLED';
}

const order: Order = {
  id: 101,
  customerName: 'Acme Retail',
  total: 125.50,
  status: 'NEW'
};

Cover interface, type, optional properties, unions, generic types, classes, async/await and strict null checks. For money, remember JavaScript number is floating point—use minor currency units or appropriate decimal processing with the backend.

5. Standalone components and template binding

Standalone components declare their template dependencies in imports. Modern templates can use built-in control flow such as @if and @for.

import { Component, signal } from '@angular/core';

@Component({
  selector: 'app-order-counter',
  standalone: true,
  template: `
    <h2>Orders reviewed: {{ count() }}</h2>
    <button (click)="increment()">Review another</button>
    @if (count() > 0) {
      <p>Review session started</p>
    }
  `
})
export class OrderCounterComponent {
  count = signal(0);
  increment() { this.count.update(v => v + 1); }
}

Learn interpolation, property binding, event binding, two-way binding where appropriate, component inputs/outputs, and accessibility labels.

6. Routing and lazy loading

Router configuration maps path segments to components. Prefer lazy loading for independently navigable feature views.

import { Routes } from '@angular/router';

export const routes: Routes = [
  { path: '', redirectTo: 'orders', pathMatch: 'full' },
  {
    path: 'orders',
    loadComponent: () => import('./features/orders/orders.component')
      .then(m => m.OrdersComponent)
  },
  { path: '**', redirectTo: 'orders' }
];

Exercise: add an order details route with a URL parameter, and include a link back to the list. A route guard can improve UX but must not be the server's authorization boundary.

7. Services, dependency injection and REST APIs

Use Angular HttpClient through dependency injection. Configure it at application bootstrap with provideHttpClient(), then call your Spring Boot API.

import { Injectable, inject } from '@angular/core';
import { HttpClient } from '@angular/common/http';
import { Observable } from 'rxjs';

export interface OrderSummary {
  id: number;
  customerName: string;
  status: string;
}

@Injectable({ providedIn: 'root' })
export class OrdersApiService {
  private http = inject(HttpClient);
  list(): Observable<OrderSummary[]> {
    return this.http.get<OrderSummary[]>('/api/orders');
  }
}

The generic type on get<T> is a compile-time expectation, not runtime schema validation. For real applications, account for failures, retry policy, cancellation, timeouts and pagination.

When the Angular dev server and API use different origins, configure a development proxy or narrowly scoped CORS on the backend. A production gateway can serve both under one origin.

8. Reactive forms and validation

Reactive forms provide a model-driven way to validate user input. Common controls include FormControl, FormGroup, and built-in validators.

import { FormControl, FormGroup, Validators } from '@angular/forms';

orderForm = new FormGroup({
  customerName: new FormControl('', {
    nonNullable: true,
    validators: [Validators.required, Validators.maxLength(80)]
  }),
  quantity: new FormControl(1, {
    nonNullable: true,
    validators: [Validators.required, Validators.min(1)]
  })
});

Validate again on Spring Boot; browser validation is for user experience, never a substitute for backend rules. Add accessible error messages and disable submission while a request is in flight.

9. Security: Angular + Keycloak + Spring Boot

For a browser-based Angular application, a common standards-based option is OAuth 2.0 Authorization Code Flow with PKCE using a Keycloak public client, or a Backend-for-Frontend pattern when server-side session management is required.

  • Register the exact application redirect URIs and web origins in Keycloak; avoid broad wildcards.
  • Do not embed client secrets in frontend JavaScript or configuration.
  • Validate tokens, issuer, audience and authorities in the Spring Boot Resource Server or BFF as appropriate.
  • Do not rely on hiding Angular buttons or routes to enforce authorization.
  • Prefer short-lived access tokens; assess token storage, XSS and CSRF risks according to your chosen architecture.
Do not implement an improvised login form that collects Keycloak credentials inside Angular. Use an established OIDC integration and the provider's authorization endpoint.

10. Tests, tooling and production build

Write component tests for rendering and interactions, service tests using HTTP test utilities, and browser-level tests for the order workflow. Make tests independent of a live database where practical.

ng test
ng build

Inspect the Angular CLI version's generated testing configuration rather than assuming a specific runner. Use linting/formatting appropriate to your team's conventions, keep npm dependencies updated, and review production build budgets.

Deployment concerns include caching hashed assets, SPA fallback routing, TLS, environment-specific API base URLs, and centralized monitoring.

11. Hands-on capstone: Order Management SPA

Scenario: Build an Angular client for an existing secured Spring Boot Order API. Deliver a portfolio-quality proof of concept without storing real customer data.

  1. Initialize the project and Git repository; create a feature branch.
  2. Define typed OrderSummary and OrderDetail models.
  3. Build a paginated list view with loading, empty and error states.
  4. Add a details route and a reactive order form with validation.
  5. Consume GET /api/orders and a create/update endpoint using a service.
  6. Integrate Keycloak OIDC with PKCE or a documented BFF architecture; enforce authorization in the backend.
  7. Write tests for one component and one API service.
  8. Run production build and document how to reproduce the results.

Submission: Git repository, screenshots, README with setup and configuration, security notes, and evidence of tests and production build.
