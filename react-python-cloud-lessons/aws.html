1. Shared cloud architecture

Cloud platforms provide on-demand infrastructure and managed services. The shared responsibility model separates provider infrastructure obligations from customer workloads, data and access decisions.

Service modelCustomer typically manages
IaaSGuest OS, runtime, application, data, identities
PaaSApplication, data, identities and configuration
SaaSData, user permissions, identity and tenant configuration

2. Networking and IAM fundamentals

Learn virtual networks, subnets, routes, firewalls/security groups, load balancers, public versus private endpoints, DNS and certificates. Identity policies must follow least privilege.

  • Choose a region and documented network boundaries.
  • Use short-lived workload credentials and managed identities instead of static access keys.
  • Separate development and production environments.
  • Enable audit logs, monitoring and budget alerts before deploying resources.

3. Cloud-native Spring Boot architecture

An enterprise pattern is browser → TLS ingress/load balancer → Spring Boot workload → managed database, with IAM-bound service identity, secrets manager, logs, traces and metrics.

Make authorization enforcement explicit at the API and the database boundary; a browser login alone does not secure services.

4. AWS account setup and CLI

Enable MFA on the root account, avoid using root for daily activity, use IAM Identity Center where appropriate and set up a budget. Install AWS CLI v2.

aws --version
aws configure sso
aws sso login --profile internship
aws sts get-caller-identity --profile internship

Use a dedicated sandbox account and bounded permissions; commands may require preconfigured Identity Center access.

6. Lab: serverless object upload

Create a sandbox S3 bucket with default encryption, Block Public Access and a limited IAM role. Upload a test file using a temporary IAM Identity Center profile.

aws s3 ls --profile internship
# Replace with a unique bucket you already created in the sandbox:
aws s3 cp sample.txt s3://YOUR-SANDBOX-BUCKET/sample.txt --profile internship
aws s3 ls s3://YOUR-SANDBOX-BUCKET/ --profile internship

Delete test objects and bucket afterward to avoid costs. Do not disable public-access controls.

7. Operations, security and cost

  • CloudWatch for logs and metrics.
  • CloudTrail for API auditing.
  • IAM policy simulator and Access Analyzer for least privilege.
  • Budgets and Cost Explorer for cost visibility.
  • Backup and disaster recovery objectives for critical data.

8. Capstone

Design a secure Spring Boot Orders API deployed to an AWS managed compute service with managed MySQL, private networking, workload identity, audit logs and cost estimate. Deliver a network/data-flow diagram, runbook and threat model.
