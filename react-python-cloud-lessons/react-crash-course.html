1. React mental model

React is a component-based JavaScript UI library. A React application runs in the browser, while Spring Boot exposes REST APIs and independently enforces authorization.

ConcernResponsibility
React componentsRender and update the UI from props and state
HooksManage local state, effects and reusable behavior
React RouterHandle client-side URLs when configured
Spring BootValidate input, apply business rules and authorize API access
Keycloak/OIDCAuthenticate users and issue tokens; the browser is not a trusted authorization boundary

2. Install Node.js and create a React project

Use a currently supported Node.js LTS release and npm. Vite provides a lightweight React application scaffold. Verify the Node.js requirements for the selected Vite version.

node --version
npm --version
npm create vite@latest internship-react -- --template react-ts
cd internship-react
npm install
npm run dev

Open the local URL printed by Vite. For Windows, run these commands in PowerShell; for macOS/Linux, use a terminal. Install Node from an approved installer or version manager.

3. TypeScript, JSX and components

Use TypeScript interfaces for type-checking, but validate external JSON at runtime.

type Order = { id: number; customer: string; status: "NEW" | "PAID" };

function OrderCard({ order }: { order: Order }) {
  return <article><strong>#{order.id}</strong> {order.customer} — {order.status}</article>;
}
export default OrderCard;

Separate display components from data access and business rules. Give interactive elements accessible labels.

4. State, events and rendering

State represents UI data that triggers rerendering. Never mutate state directly. Keep derived values derived, rather than duplicating them.

import { useState } from "react";
export function Counter() {
  const [count, setCount] = useState(0);
  return <button onClick={() => setCount(c => c + 1)}>Reviewed: {count}</button>;
}

Exercises: add a search term, filter an array, and use a stable record ID as a list key.

5. Effects and REST data

Fetch asynchronously using an effect or an appropriate data-fetching library. Handle loading, HTTP errors, stale requests and component cleanup.

import { useEffect, useState } from "react";
type Order = { id: number; customer: string };
export function Orders() {
  const [orders, setOrders] = useState<Order[]>([]);
  const [error, setError] = useState("");
  useEffect(() => {
    const controller = new AbortController();
    fetch("/api/orders", { signal: controller.signal })
      .then(r => { if (!r.ok) throw new Error(`HTTP ${r.status}`); return r.json(); })
      .then(data => setOrders(data))
      .catch(e => { if (e.name !== "AbortError") setError(e.message); });
    return () => controller.abort();
  }, []);
  return <div>{error || orders.map(o => <p key={o.id}>{o.customer}</p>)}</div>;
}

Use a development proxy for a locally separate backend; CORS is a server-side policy, not a React setting.

6. Routing and forms

Add React Router if the application has multiple views. Use controlled fields and validate on the server, even if browser validation runs first.

import { useState } from "react";
function CustomerForm() {
  const [name, setName] = useState("");
  return <form onSubmit={e => { e.preventDefault(); console.log(name); }}>
    <label>Customer <input value={name} onChange={e => setName(e.target.value)} required /></label>
    <button type="submit">Save</button>
  </form>;
}

Exercise: add list, details and new-order routes, each with loading/error states.

7. Enterprise security and OIDC

For a browser-based React app, use Authorization Code with PKCE through a supported OIDC library. Prefer secure backend-for-frontend architecture when appropriate; avoid embedding client secrets in the browser.

  • Never trust client-side route guards as authorization.
  • Use HTTPS, strict redirect URIs and security headers.
  • Keep access tokens out of persistent browser storage where practical; evaluate a backend-for-frontend for stronger session handling.
  • Protect Spring Boot APIs with JWT validation, issuer/audience checks and business authorization.

8. Testing and delivery

Use component tests for rendering and interactions, API mocking for error states, and end-to-end tests for user journeys.

npm run build
npm run lint

The build generates static assets; host them behind an appropriate web server/CDN and configure API origins separately. Inspect bundle size and avoid committing secrets.
