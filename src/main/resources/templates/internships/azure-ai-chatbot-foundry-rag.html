01. Architecture diagram — eight connected layers

The image shows channels → application and identity → Foundry/orchestration → AI Search retrieval → Azure OpenAI inference, with optional enterprise tools, a separate knowledge ingestion flow, and cross-cutting governance and operations.

Diagram interpretation: This is a reference architecture, not a mandatory product dependency chain. Azure AI Search performs retrieval, while an embedding model creates vectors. The application must enforce user authorization; simply retrieving a passage does not make it safe to disclose.

02. What the architecture accomplishes

An enterprise assistant answers employee and customer questions using trusted organizational knowledge while respecting identity, document permissions and business-system boundaries. RAG retrieves relevant passages for grounding; an optional agent can call approved tools for live data or controlled actions.

Example user question“Where is order 47821 and when will it ship?”
Knowledge pathFind shipping policy documents via Azure AI Search.
Live business pathCheck current order status through an authorized Orders API.
AnswerCombine retrieved policy context and authorized live status, cite sources, and avoid inventing unsupported facts.

03. Users, channels and front-end application layer

The same backend can serve a browser, mobile UI, Teams integration or external API clients. Each request must carry an authenticated user context, while the backend enforces role-based access and data entitlements.

Web & mobileHTTPS and user login through Microsoft Entra ID or a federated IdP.
Backend API gatewayValidate tokens; enforce throttling, quotas and request limits.
Conversation historyUse an app-managed state store such as Cosmos DB; apply retention and privacy policies.
Security distinctionAn authenticated user is not automatically entitled to every document or tool.

04. Microsoft Foundry and application orchestration

Microsoft Foundry provides a platform for creating, evaluating, managing and governing AI solutions. The actual orchestration can be implemented using Foundry agent capabilities or a custom backend. Foundry is not itself a mandatory proxy that every user prompt must pass through.

ModelsChoose deployments and settings appropriate to cost, latency, capabilities and compliance.
Prompt orchestrationApply system instructions, conversation context and retrieved evidence.
Agent operationsOptional tool selection and structured tool calls for approved workflows.
EvaluationTest groundedness, retrieval relevance, accuracy, safety and cost before release.

05. Azure OpenAI inference and embedding models

Azure OpenAI provides model inference for answer generation and, when selected, embeddings. Chat and embedding deployments serve distinct purposes. The model does not automatically know proprietary enterprise documents.

Chat modelGenerates a response from instructions, conversation and retrieved context.
Embedding modelTransforms text into numerical vectors for semantic similarity.
Token budgetingRetrieved passages consume context space; excessive material increases latency and cost.
SafetyValidate generated outputs and tool arguments; don't assume model output is always correct.

06. Knowledge ingestion pipeline

Documents are acquired from SharePoint, PDFs, Word, Azure Blob Storage, databases or governed repositories. Each source requires a permission-aware connector and change detection. A pipeline extracts text, splits passages, enriches metadata, creates embeddings, and indexes authorized content.

Step 1 — ingestRetrieve permitted source files and metadata; track source IDs and last-modified timestamps.
Step 2 — parseExtract text, tables and document structure; use OCR only when needed.
Step 3 — chunkSplit into useful passages with overlap and stable source identifiers.
Step 4 — embedGenerate vectors using the chosen embedding deployment.
Step 5 — indexStore searchable fields, text, embeddings, source URLs and authorization metadata.
Step 6 — refreshHandle updates, removals and entitlement changes; prevent stale records from lingering.

07. Azure AI Search — indexes, hybrid retrieval and ranking

Azure AI Search indexes both searchable text and vector fields. Hybrid retrieval combines lexical matching with vector similarity; optional semantic ranking can rerank or enrich results. Search is a retrieval engine, not the chatbot's language model.

Keyword searchFinds exact terms, IDs and rare product names.
Vector searchFinds semantically similar passages even with different wording.
Hybrid searchCombines both methods for broader recall.
Semantic rankingOptionally reranks eligible results by semantic relevance.
Security trimmingApply document ACL filters using trusted identities and index metadata before sending passages to the model.

08. RAG request flow explained step by step

The backend authenticates the user, turns the question into a search query, retrieves passages allowed for that user, builds a bounded prompt with evidence, calls the model, checks the answer and returns it with citations.

1. ReceiveUser sends a question through the UI over HTTPS.
2. AuthorizeResolve the user and their entitlements; determine tool permissions.
3. RetrieveSearch the index using hybrid retrieval and permission filters.
4. GroundAttach short, relevant excerpts with citations to the prompt.
5. GenerateCall the Azure OpenAI chat model.
6. ValidateCheck citations, policy constraints and unsupported assertions.
7. RespondReturn answer with source links and optionally stream tokens to the UI.

09. Business tools, APIs and optional agent actions

An assistant may need current data that is not in the search index. Give the agent narrowly scoped tools backed by trusted REST APIs, and authorize each call server-side.

Read-only toolsFetch an order status, inventory count or support ticket.
Mutating toolsUpdate a ticket or cancel an order only after confirmation and authorization.
Execution safetyUse allowlists, timeouts, validation, rate limits, audit trails and least-privilege credentials.
Trust boundaryRetrieved documents and tool outputs are untrusted data; never treat their instructions as higher-priority rules.

10. Identity, document permissions and access control

Microsoft Entra ID authenticates workforce users and workloads. Application authorization, API authorization, and document-level permission checks are separate layers. Managed identity supports service-to-service token access without hardcoded client secrets.

User identityOIDC authorization-code login; protect sessions and CSRF where appropriate.
API identityValidate issuer, audience, expiry, signature and required scopes/roles.
Document ACLFilter Azure AI Search retrieval to the user's permitted documents.
Managed identityGrant the backend minimum data-plane access to search, models and storage.
Key VaultStore third-party secrets or certificates when secretless authentication is not supported.

11. Private networking and high availability

For a production deployment, choose the available private endpoint and network isolation features for the specific Azure services and SKUs. Protect external APIs with WAF/rate limits; plan model and search capacity and regional resiliency deliberately.

IngressFront Door/WAF optionally routes users to healthy web application origins.
VNet connectivityPrivate endpoints and correct DNS resolution reduce public exposure where supported.
AvailabilityUse zone or regional redundancy, retries and capacity controls as supported.
Disaster recoveryBack up index definitions and source data; document reindexing and failover procedures.

12. Monitoring, evaluation and AI governance

Monitor request traces, backend latency, search quality, model token usage and errors. Use Azure Monitor/Application Insights and Foundry evaluations to test security and response quality.

Operational metricsRequest rate, p95 latency, failures, throttling and dependency health.
AI quality metricsRetrieval precision, groundedness, refusal quality and citation coverage.
PrivacyMinimize PII in prompts and logs; configure retention and access policies.
Financial controlTrack model tokens, embedding volume, search replicas/partitions and compute costs.

13. CI/CD and production lifecycle

Use source control and automated environments for code, prompts, indexing schema, API policies and infrastructure. Treat evaluations and security scans as release gates.

Source controlVersion application code, prompt templates, data schemas, tool definitions and infrastructure.
DeployProvision Azure resources with Bicep or Terraform; use managed identities and environment-specific settings.
ValidateRun tests for retrieval relevance, user access restrictions, tool permissions and regressions.
ReleaseRoll out gradually, monitor quality and support rollback.

Each Azure service has a distinct responsibility, and removing any one component changes the system's capabilities.

15. Failure handling and troubleshooting

Enterprise chatbots fail in different ways: a valid model answer can be grounded in the wrong document; a correct retrieval can still expose an unauthorized document; a working search can coexist with a slow or throttled model.

401/403Check token audience/scopes, managed identity role assignments and document filters.
Search returns nothingInspect index schema, ingestion freshness, query strategy and ACL filtering.
Wrong or invented answerReview grounding context, prompts, retrieval ranking and citation requirements.
429 throttlingInspect deployment quota, client concurrency and retry with backoff.
High latencyBreak down search, model, tool-call and network timings.
Stale dataReview ingestion jobs, delete propagation and synchronization schedules.

16. Worked example — Spring Boot order-support chatbot

Suppose an authenticated retail employee asks: “Why was order 47821 delayed, and what is our shipping-delay policy?” The application has to obtain the policy from trusted documents and the current order status from a separate live API.

StageExample actionSecurity requirement
1. LoginUser authenticates to a Spring Boot UI via Microsoft Entra ID or Keycloak.Validate session, issuer and privileges.
2. Policy searchBackend queries Azure AI Search for shipping-delay policy passages.Filter by employee/document entitlements.
3. Live order toolBackend invokes GET /orders/47821 in the secured Orders API.Check access to the specific order.
4. Grounded promptSelected policy excerpt and current order status become model context.Exclude secrets, irrelevant personal data and untrusted instructions.
5. CompletionAzure OpenAI creates a concise answer citing the policy source.Verify claims; surface unknowns instead of inventing.
6. AuditLog retrieval, tool call, correlation ID and latency appropriately.Privacy-safe telemetry and retention.

Illustrative request/response contract

POST /api/chat
Authorization: Bearer <access-token>
Content-Type: application/json

{
  "conversationId": "c-140",
  "question": "Why was order 47821 delayed?"
}

Response:
{
  "answer": "The order status shows a carrier delay. ...",
  "citations": [
    {"title": "Shipping Delay Policy", "sourceId": "POL-104"}
  ],
  "correlationId": "trace-89"
}
Trust boundary: The LLM does not authorize orders or documents. Your Spring Security resource server and trusted backend services enforce access before context is supplied to the model.

17. Enterprise capstone architecture assignment

Scenario: A retail organization needs a chatbot for employees and approved suppliers. It must answer questions from SharePoint policy documents, retrieve real-time order information, and create a support ticket only after user confirmation.

  1. Draw browser/Teams channels, API gateway, Spring Boot orchestration, identity provider, Foundry, Azure OpenAI, AI Search and business APIs.
  2. Design an ingestion pipeline with extraction, chunking, vector embeddings, metadata and access control lists.
  3. Describe a hybrid retrieval strategy and citation structure.
  4. Provide an identity and authorization matrix for employees, suppliers and service identities.
  5. Model safe tool calls, human approval for ticket creation, retries and audit logs.
  6. Define test cases for hallucinations, prompt injection, deleted documents and permission changes.
  7. Define availability, observability and cost budgets for production.

Submission: Architecture diagram, request sequence, threat model, roles matrix, document index design and a short Spring Boot proof of concept.
