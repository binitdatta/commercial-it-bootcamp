2. Azure Data Factory in simple English

Imagine a large retail business with hundreds of stores. Its information is scattered across cash registers, an accounting database, Salesforce, Excel spreadsheets and external supplier websites. Analysts want one reliable, regularly updated dataset for sales and inventory decisions.

Azure Data Factory (ADF) is the conductor that coordinates how information moves from those sources into a central destination. Just as a logistics coordinator arranges pickup, inspection, packaging, delivery and tracking, ADF can schedule extraction, execute transformations, call supporting services, load data and record the results.

Warehouse / logistics activityAzure Data Factory equivalent
Identify which suppliers and warehouses hold goodsConnections to data sources (linked services)
Arrange the pickup vehicle and routeIntegration Runtime and copy activities
Inspect, clean and repackage shipmentsMapping Data Flows or another compute engine
Deliver labeled boxes to a central warehouseWrite datasets to ADLS Gen2, Blob Storage or databases
Choose pickup times and monitor exceptionsTriggers, pipeline orchestration, monitoring and alerts
Fundamental distinction: ADF is primarily a managed data-integration and orchestration service. It can execute transformation activities, but the heavy compute work runs on engines such as Mapping Data Flow Spark clusters, SQL, Databricks, Azure Functions or other integrated services.

Data Factory is not a replacement for your source applications, data lake, relational database or reporting solution. It is the orchestration layer that connects those systems into a dependable workflow.

5. Azure Integration Runtime vs Self-hosted Integration Runtime

The Integration Runtime is the execution and connectivity infrastructure that helps ADF perform data movement and dispatch selected activities to other compute resources. Selecting the correct IR is essential when integrating cloud data with private corporate networks.

CategoryAzure IRSelf-hosted IR
Where it runsMicrosoft-managed infrastructure.Your managed Windows host or VM.
Common useCloud data movement, activity dispatch; managed execution for mapping data flows.Access on-premises or private-network sources/sinks for supported activities.
OperationsAzure manages underlying IR infrastructure.You patch, scale and monitor the host and its network connectivity.
ExampleCopy Azure SQL to ADLS.Read SQL Server inside a corporate datacenter.
ConsiderationsRegional placement, networking, performance and costs.Outbound connectivity, host availability, drivers and credential security.
Important: Self-hosted IR is not a full substitute for Azure IR. Mapping Data Flow executions use Azure IR-managed compute; a self-hosted IR is primarily used for source/sink connectivity and supported activities.

6. Ingest data using Copy Activity

Copy Activity reads data from a supported source and writes it to a supported destination. Depending on the connector and format, it can apply basic mappings and type conversions. It is usually the first tool to consider for a straightforward data transfer.

  1. Create the source linked service, such as Azure SQL Database.
  2. Create the destination linked service for ADLS Gen2.
  3. Define source and sink datasets, including path and format.
  4. Add Copy Activity to a pipeline and choose both datasets.
  5. Configure column mappings, fault tolerance, authentication and IR.
  6. Debug or trigger a run and inspect rows read, written, duration and errors.

7. Processing and transforming data

ADF's Mapping Data Flows provide a visual, Spark-based transformation experience. You can join multiple inputs, filter rows, derive columns, aggregate values, detect data quality issues and write transformed results.

TransformationPurposeRetail example
FilterExclude irrelevant rows.Keep completed transactions only.
Derived columnCreate computed fields.netSales = grossSales - discount.
JoinCombine datasets using keys.Join orders with product reference data.
AggregateSummarize by dimensions.Daily revenue by store.
ValidationCheck nulls, schema and business constraints.Reject records without order IDs.
Sink formattingProduce output in a specified format.Delimited CSV in ADLS Gen2.

ETL vs ELT

ETL transforms data before loading the final destination. ELT first loads the raw data into a platform such as a data lake or warehouse, then uses its compute engine to transform it. ADF can orchestrate either design.

8. Integrating external REST APIs with Azure Functions

Your diagram includes a Function that authenticates to an external API, calls an endpoint, parses JSON or XML, and converts the response to CSV. This is a reasonable architecture when the external API requires custom token handling, pagination, response normalization or other logic unsupported by a direct connector.

  1. ADF invokes an Azure Function or HTTP endpoint.
  2. The Function authenticates to the target API using credentials secured in Key Vault.
  3. The Function requests and validates the external response.
  4. The Function writes transformed data to storage or returns a small status/payload.
  5. ADF continues downstream only after successful completion.
Production caveat: Do not return huge datasets as an ADF Azure Function activity output. For large or long-running API ingestions, let the Function write data to storage and return a file reference or status, then let Copy/Data Flow process that output.

9. ADLS Gen2 — writing and organizing CSV files

Azure Data Lake Storage Gen2 uses Azure Blob Storage with the hierarchical namespace feature to support directory-oriented analytics workloads. An ADF pipeline can write CSV files directly into containers and folders, allowing Power BI, Databricks, Azure Synapse or downstream applications to access curated datasets.

Example lake directory layout

retail-datalake/
  raw/
    sql-sales/business-date=2026-10-13/
    crm-customers/business-date=2026-10-13/
    supplier-api/business-date=2026-10-13/
  curated/
    sales/business-date=2026-10-13/sales.csv
    customers/business-date=2026-10-13/customers.csv
  quarantine/
    invalid-orders/business-date=2026-10-13/

Delimited files must be configured for appropriate encoding, delimiter, quoting, null handling and header behavior. Consider Parquet rather than CSV for large analytic datasets when columnar compression and query efficiency matter.

Security requires planning both Azure RBAC and, when the hierarchical namespace is enabled, appropriate filesystem/directory ACLs for the chosen access pattern.

IssueInvestigationTypical corrective action

Pipeline times outActivity duration, data volume, service limits.Partition reads, scale compute, improve external API handling.
Duplicate output filesRetries, dynamic paths and reruns.Use idempotent writes and deterministic partitions.

Useful metrics: pipeline success rate, failed activity count, volume of data copied, bytes/rows read and written, run duration, lateness, and source API throttling.
