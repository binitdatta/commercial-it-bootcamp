1. Understanding the architecture diagram

Start with users and Azure DNS, then follow the public HTTPS connection into Application Gateway, the optional internal Layer 4 load balancer, and web/application VMs across availability zones. Hybrid access enters through either VPN Gateway or ExpressRoute, while Azure Bastion provides administration of private VMs.

Important implementation detail: This diagram is a conceptual reference, not a deployment-ready subnet plan. VPN Gateway and ExpressRoute virtual network gateways use a specially named GatewaySubnet; Azure Bastion uses AzureBastionSubnet; Application Gateway needs its own subnet. The depicted service boundaries and sample IPs must be validated before provisioning. Also, Azure DNS resolves names but is not in the application-data path.

2. Architecture diagram: follow a request from browser to VM

TopicExplanation and use case
Step 1 — DNSThe browser resolves app.contoso.com. Azure DNS can host its authoritative public DNS zone, returning a record or alias for the configured entry point.
Step 2 — connectThe browser establishes HTTPS connectivity to the public frontend of Application Gateway; TLS negotiation occurs at the gateway when TLS termination is enabled.
Step 3 — Layer 7 gatewayApplication Gateway evaluates listeners, host/path routing rules, optional WAF policy and backend health.
Step 4 — backend trafficThe gateway forwards HTTP/HTTPS to a configured backend pool. The illustration uses an internal Load Balancer before VM instances; this is optional and should be justified by the actual backend topology.
Step 5 — availabilityHealthy VM instances span availability zones where supported, and health probes prevent routing to unhealthy backends.
Administrative flowAdministrators reach private VMs through Azure Bastion, without exposing RDP/SSH ports to the public internet.
Hybrid flowAn on-premises location connects through encrypted site-to-site VPN or private ExpressRoute connectivity, depending on network requirements.

3. Azure Virtual Network, CIDR and subnet design

TopicExplanation and use case
VNetA VNet is an isolated logical network address space, such as 10.0.0.0/16, with subnets for workloads and network appliances.
Subnet isolationDedicated subnets are used for Application Gateway, web/application VMs, management resources, Bastion and gateways where required.
Real subnet namesAzure VPN Gateway and ExpressRoute virtual network gateways require a subnet named GatewaySubnet; Bastion requires AzureBastionSubnet. They are not interchangeable with application subnets.
NSGsNetwork Security Groups define stateful inbound/outbound filtering at subnet or NIC scope; they do not replace web application firewall inspection.
RoutingSystem routes provide VNet routing; UDRs can redirect traffic through inspection appliances. Route planning matters for hybrid links.

4. Azure Virtual Machines and VM Scale Sets

TopicExplanation and use case
Virtual machinesAn Azure VM provides IaaS compute where you manage the guest OS, patches, installed software, network configuration and application.
VM Scale SetsVM Scale Sets coordinate multiple similar VMs, scaling and orchestration to increase service capacity and resiliency.
Availability zonesPlace instances in multiple supported zones where requirements and SKU availability allow; use load-balancer health checks.
OS responsibilitiesAzure manages the underlying host infrastructure, but the customer remains responsible for guest OS hardening, patching and application access.
DisksAzure managed disks provide block storage; plan backup, redundancy and persistence separately from compute availability.

5. Azure Load Balancer — Layer 4

TopicExplanation and use case
OSI Layer 4Azure Load Balancer distributes TCP/UDP flows using frontend IP configuration, rules, backend pools and health probes.
Internal vs publicA public Load Balancer has an internet-reachable frontend; an internal Load Balancer has a private frontend inside a VNet.
Health probesA probe determines which backend instances can receive new traffic.
No WAFLoad Balancer does not examine URLs, HTTP headers, cookies or SQL injection patterns; it is not a Layer 7 WAF.
Common useLoad-balance VM application servers, non-HTTP services and private microservice tiers.

6. Azure Application Gateway — Layer 7 and WAF

TopicExplanation and use case
Layer 7 routingApplication Gateway understands HTTP(S) requests and supports host-based/path-based routing.
TLSIt can terminate TLS and optionally re-encrypt to backends; configure certificates and backend trust appropriately.
WAFThe WAF SKU applies web attack rules and policies for applicable traffic, including OWASP-oriented detections and custom rules.
Backend poolsBackends can be VMs, scale sets, IP addresses/FQDNs and supported services, depending on configuration.
Dedicated subnetDeploy Application Gateway in its own subnet and verify minimum size requirements for the chosen deployment mode.
ContrastFor worldwide anycast edge entry and cross-region routing, compare Azure Front Door; Application Gateway is regional.

7. Azure DNS — public and private name resolution

TopicExplanation and use case
Public zonesAzure DNS hosts authoritative public DNS zones. A domain registrar still controls registration and delegation to authoritative name servers.
DNS lookupRecursive resolvers obtain DNS records that direct clients to the selected public endpoint. DNS does not carry the actual HTTP request.
Private DNSAzure Private DNS zones support private names inside linked VNets and private endpoint scenarios.
Hybrid resolutionFor on-premises and Azure cross-boundary DNS, plan conditional forwarding and Azure DNS Private Resolver where appropriate.
Operational concernDNS caching and TTL can delay address changes; DNS-based failover is not identical to health-aware application routing.

8. VPN Gateway — encrypted hybrid connectivity

TopicExplanation and use case
Site-to-site VPNIPsec/IKE tunnels traverse the internet between an on-premises VPN device and Azure VPN Gateway.
Point-to-site VPNIndividual client devices can securely connect into the VNet when configured.
Network requirementsProvide non-overlapping address spaces and align routes, gateway SKU, throughput and tunnel settings.
GatewaySubnetUse the reserved GatewaySubnet for the virtual network gateway; AzureBastionSubnet serves a different service.
TradeoffThe VPN encrypts traffic, but it still travels over public-internet transport with variable latency.

9. ExpressRoute — enterprise private connectivity

TopicExplanation and use case
Private circuitExpressRoute connects an enterprise network to Microsoft cloud services through a connectivity provider, without relying on public internet transit for the circuit.
GatewayAn ExpressRoute virtual network gateway can connect the circuit to an Azure VNet, subject to the specific architecture.
BGPBGP is typically used for routing exchange on ExpressRoute private peering.
Encryption caveatExpressRoute private connectivity is not automatically end-to-end encrypted. Use application TLS or another encryption mechanism where required.
ResiliencyPlan redundant connections, diverse paths, failover and capacity; a private circuit alone does not guarantee end-to-end application availability.

10. Azure Bastion — secure administration

TopicExplanation and use case
No public VM IPAzure Bastion provides browser-based RDP/SSH to supported VMs using private IP addresses, avoiding direct public VM management ports.
Bastion subnetThe deployment requires AzureBastionSubnet with supported subnet sizing (commonly /26 or larger for current deployment SKUs).
Management accessRBAC, VM credentials, network rules and Bastion SKU features must be configured; Bastion does not automatically grant OS login rights.
AuditabilityUse appropriate Azure Monitor and VM activity logging, plus just-in-time access controls where applicable.
When to useAdministrator break-glass access, operational maintenance and controlled troubleshooting.

11. Which component should you choose?

TopicExplanation and use case
Azure DNSAnswer name-resolution questions. It is not a reverse proxy.
Application GatewayUse regional HTTP(S) routing, TLS termination and optionally WAF.
Azure Load BalancerUse Layer 4 TCP/UDP balancing for public or internal workloads.
Azure Front DoorUse global edge HTTP(S) acceleration, WAF and cross-region routing.
VPN GatewayUse encrypted tunnels for hybrid connectivity over public internet.
ExpressRouteUse private, predictable enterprise connectivity; add encryption as needed.
BastionUse controlled RDP/SSH access to private VMs.

12. Defense in depth: network, identity and transport

TopicExplanation and use case
PerimeterProtect web entry with WAF policies, rate limits and DDoS posture suited to each application.
NetworkUse NSGs, routes, firewalls and Private Link to constrain east-west and outbound reachability.
IdentityUse Entra ID, Azure RBAC and workload identities; these control different privileges than network ACLs.
TransportUse HTTPS/TLS for client-to-gateway and gateway-to-backend traffic where appropriate; secure hybrid traffic separately.
MonitoringConfigure Azure Monitor, connection diagnostics, gateway access/WAF logs, VM metrics and alert routing.

13. High availability and recovery planning

TopicExplanation and use case
Zone redundancySpread VM backends across supported zones and configure health probes.
Gateway HAChoose zone-redundant Application Gateway configurations where supported and size gateway instances appropriately.
Regional failureAn architecture in one region does not survive full-region failure by default; use cross-region architecture and Front Door or another global routing strategy.
Hybrid outagesTest failure of VPN tunnels, ExpressRoute circuits, DNS resolvers and on-premises network devices.
DatabasesApplication redundancy does not automatically provide database redundancy; use suitable SQL HA/DR services.

14. End-to-end Spring Boot workload example

TopicExplanation and use case
Web entryA customer accesses https://app.contoso.com; Azure DNS resolves the hostname to Application Gateway public entry.
TLS and authenticationApplication Gateway terminates or passes through TLS per policy; Spring Security authenticates bearer tokens and authorizes REST API requests.
Load distributionApplication Gateway distributes HTTP traffic to healthy Spring Boot VM backends, optionally behind an internal L4 load balancer if the topology needs it.
DatabaseThe service accesses a private managed SQL database or SQL Server on a controlled subnet over approved ports.
AdministrationSupport engineers use Azure Bastion for a private VM session, while hybrid dependencies connect through VPN or ExpressRoute.

15. Common operational problems and how to reason about them

TopicExplanation and use case
502 from Application GatewayCheck backend health probes, listener/protocol settings, DNS resolution, TLS certificates and VM application availability.
Cannot reach VM via BastionCheck AzureBastionSubnet, SKU, NSG rules, target private IP, RBAC and guest OS login/RDP/SSH.
VPN tunnel is downCheck on-premises peer public IP, IKE/IPsec configuration, pre-shared keys, routes and gateway diagnostics.
ExpressRoute route missingReview BGP session, private peering, route propagation and VNet gateway association.
DNS wrong addressCheck authoritative zone records, VNet-private DNS links, resolvers, split-horizon settings and cached TTL.
One VM overloadedReview health probes, connection distribution, autoscaling policies and application metrics.

17. Enterprise capstone — design a secure two-tier web application

Scenario: An organization hosts its order-management Spring Boot REST APIs on four Azure VMs across two availability zones. It needs one HTTPS entry point, private administrative access, hybrid connectivity to an existing datacenter, and controlled outbound access.

  1. Draw a VNet and non-overlapping subnet plan for Application Gateway, application VMs, GatewaySubnet and AzureBastionSubnet.
  2. Configure the conceptual DNS entry for orders.example.com and its relationship to the public gateway frontend.
  3. Pick a WAF policy, listeners, HTTPS certificate, backend pool, routing rules and health probes.
  4. Explain why a separate internal Load Balancer is optional for HTTP traffic already routed by Application Gateway.
  5. Identify NSG rules permitting only required client, gateway, application, database and management flows.
  6. Choose VPN Gateway or ExpressRoute and explain bandwidth, security, cost and availability trade-offs.
  7. Propose multi-zone VM deployment, autoscaling/patching, Azure Monitor alerts and backup/DR requirements.
  8. Describe Spring Security JWT validation and the separation between application authorization and infrastructure access.

Submission artifacts: infrastructure architecture, CIDR plan, network port matrix, identity/access matrix, security controls, recovery scenario and cost assumptions.
