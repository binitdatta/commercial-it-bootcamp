Azure Virtual Networks: Two Customers, One Physical Infrastructure

Learn how two companies can safely operate separate networks and workloads even when the cloud provider uses shared physical servers.

1 Study the architecture

Read it top to bottom: Two companies each get a logically separate private network with dedicated address plans and security policies. Those networks run on Azure's shared, software-defined networking and physical compute infrastructure. The same physical hardware does not mean the companies share operating systems, disks or network permissions.

The diagram is conceptual, not a representation of a specific Azure customer's hardware placement or a guarantee that both customers occupy the same individual host.

2 First, understand the name: Azure VNet versus VPC

The illustration uses the generic label Virtual Private Cloud (VPC). In Microsoft Azure, the actual networking resource is called an Azure Virtual Network (VNet). Amazon Web Services calls its analogous networking resource an Amazon VPC. This lesson uses Azure's correct product names.

General conceptAzure terminologyAWS terminology
Customer-defined private cloud networkVirtual Network (VNet)Virtual Private Cloud (VPC)
Network segmentSubnetSubnet

Key idea: This is a logical networking boundary, not an individually owned physical datacenter or a reserved physical switch.

5 How can the same physical hardware remain private?

Two independent boundaries work together: compute isolation and network isolation. They are related, but not interchangeable.

Compute and data isolation

  • Each VM operates with its own guest OS and virtualized resources.
  • The hypervisor enforces separation between VM execution environments.
  • Disks and data access are governed by storage and identity controls.
  • Sharing a host does not grant one customer's VM access to another's memory or data.

Network isolation

  • Each VNet has its own routing context and chosen private address space.
  • No direct cross-VNet connection exists by default.
  • NSGs and firewalls further restrict allowed communication.
  • VNet peering, VPNs or other configured paths can introduce connectivity intentionally.
Crucial distinction: Different customer subscriptions, Microsoft Entra tenants, VNets, VM boundaries and database permissions are different controls. Never assume one automatically replaces another.

8 Five common misconceptions

MisconceptionCorrect explanation
"An Azure VPC is the standard resource name."Azure uses Virtual Network (VNet); AWS uses VPC.
"One subnet cannot talk to another subnet."Subnet separation alone is not a deny rule; Azure provides default intra-VNet connectivity subject to policies and routes.
"All tenants must have globally unique private IP addresses."Private address ranges may overlap across isolated VNets; overlap becomes relevant when connecting networks.
"An NSG encrypts all traffic."NSGs filter network flows; encryption requires TLS, VPN or other applicable mechanisms.
"Sharing a physical server means sharing data."Host virtualization, storage access controls and identity boundaries are designed to isolate customer workloads and data.

9 Knowledge check

1. What is the Azure equivalent of an AWS VPC?

Azure Virtual Network (VNet).

2. Is a subnet automatically isolated from other subnets in its VNet?

No. Routing and traffic filtering policies determine whether traffic can flow between subnets.

3. What is the difference between an NSG and a route table?

The NSG controls allowed/denied flows; a route table determines where packets are forwarded.

4. Can customers use overlapping IP ranges?

Yes, when their networks are isolated. Direct connectivity between overlapping networks requires additional design because ambiguous routing is a problem.

5. Does a VM hypervisor replace database authorization?

No. Compute isolation and database authentication/authorization address different security boundaries.
