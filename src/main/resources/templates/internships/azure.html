1. Shared cloud architecture

Cloud platforms provide on-demand infrastructure and managed services. The shared responsibility model separates provider infrastructure obligations from customer workloads, data and access decisions.

Service modelCustomer typically manages
IaaSGuest OS, runtime, application, data, identities
PaaSApplication, data, identities and configuration
SaaSData, user permissions, identity and tenant configuration

2. Networking and IAM fundamentals

Learn virtual networks, subnets, routes, firewalls/security groups, load balancers, public versus private endpoints, DNS and certificates. Identity policies must follow least privilege.

  • Choose a region and documented network boundaries.
  • Use short-lived workload credentials and managed identities instead of static access keys.
  • Separate development and production environments.
  • Enable audit logs, monitoring and budget alerts before deploying resources.

3. Cloud-native Spring Boot architecture

An enterprise pattern is browser → TLS ingress/load balancer → Spring Boot workload → managed database, with IAM-bound service identity, secrets manager, logs, traces and metrics.

Make authorization enforcement explicit at the API and the database boundary; a browser login alone does not secure services.

4. Azure subscriptions, resource groups and CLI

Use a sandbox subscription, a resource group and Microsoft Entra ID identities. Azure RBAC governs resource access; application authentication and data access remain separate concerns.

az version
az login
az account show --output table
az group list --output table

Set budgets and resource policy guardrails before provisioning paid services.

6. Lab: resource group and managed identity planning

Inspect existing sandbox resources first, then plan an Azure Container Apps deployment with a managed identity, Key Vault access and observability.

az account show --output table
az group list --output table
az identity list --output table
az monitor log-analytics workspace list --output table

Use the principle of least privilege; avoid embedding client secrets in Spring Boot YAML files.

7. Networking and security operations

  • Use virtual networks and private endpoints as architecture requires.
  • Apply Azure RBAC to management operations and workload identity to service access.
  • Use Azure Monitor and Log Analytics for operations.
  • Use Microsoft Defender for Cloud where appropriate and review budget usage.

8. Capstone

Architect an Azure Container Apps Spring Boot Orders API with Microsoft Entra ID or Keycloak login, managed identity to Key Vault, managed MySQL and centralized monitoring. Include a diagram and access-control matrix.
