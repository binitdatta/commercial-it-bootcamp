01 · API Gateway + Lambda reference architecture

API Gateway terminates public API requests, applies configured authorization/throttling, invokes integrated backends (including Lambda), and returns responses. It provides HTTP, REST and WebSocket API flavors with different features, quotas, and pricing.

Diagram interpretation: The infographic is a conceptual overview, not a compulsory hop-by-hop network topology. CloudFront is optional, WAF attaches to supported resources (such as an API Gateway REST API stage), and asynchronous Lambda execution is triggered by supported event sources—not by treating a synchronous API integration as automatically asynchronous. Route 53 provides DNS, not an HTTP proxy.

03 · API stages, routes, integrations and domains

Routes and methods

Define routes such as GET /orders and POST /orders; integrations route requests to Lambda or HTTP services.

Stages

Publish API configurations to environments, optionally with auto-deployment for HTTP APIs.

Custom domain names

Associate TLS certificates and API mappings; Route 53 alias records can resolve to the API endpoint.

Integration

Lambda proxy, HTTP proxy, VPC Link and supported AWS service integrations differ by API type.

04 · Request processing and response flow

Step 1. Client resolves API domain name using DNS and establishes HTTPS.
Step 2. API Gateway matches the route and runs configured authentication/authorization.
Step 3. Throttling, validation and mappings are applied where supported and configured.
Step 4. The Lambda integration invokes a function or forwards to another configured backend.
Step 5. API Gateway returns an appropriate HTTP status, headers and body to the client.

05 · Authentication and authorization

  • IAM authorization signs requests with SigV4 and is suitable for AWS-integrated callers.
  • JWT authorizers (HTTP APIs) can validate issuers/audiences such as Amazon Cognito or a compatible OIDC identity provider.
  • Lambda authorizers implement custom authorizer logic where supported.
  • Resource policies for REST APIs restrict network/account access as supported.
  • Use AWS WAF on supported API Gateway REST API stages for Layer 7 filtering; do not assume it attaches to every API type.
  • API keys and usage plans are not a substitute for authentication or fine-grained authorization.

06 · Lambda, VPC Link and backend services

Lambda proxy integration

A function receives an event describing the request; it returns the expected API proxy response shape.

Private integrations

VPC Link can access supported internal load balancers/services without exposing private backend directly.

Event-driven backend

A Lambda handler can submit jobs to SQS/EventBridge and immediately return 202 Accepted with a tracking ID.

WebSockets

Routes can invoke Lambda and publish to connected clients using the API Gateway management API.

07 · Throttling, quotas and caching

FeatureExplanation
Stage / route throttlingSet rate and burst controls within supported API types and account limits.
Usage plansREST API feature for client usage management; keys identify consumers but do not authenticate callers.
CachingStage/method cache is a REST API feature; HTTP APIs do not offer the same built-in cache feature.
TimeoutsDesign Lambda execution and API integration timeouts jointly; avoid synchronous long-running workflows.
CORSExplicitly configure origins, headers, methods and credential expectations for browser clients.

08 · Security design and API governance

  • Prefer HTTPS custom domains and managed TLS certificates through ACM.
  • Validate every request and enforce authorization at both API and downstream application layers.
  • Restrict Lambda invoke access to the intended API/route resources where feasible.
  • Avoid logging credentials, authorization headers or PII.
  • Use least-privilege IAM and segregate production/development stages and accounts.
  • Capture access logs, correlation IDs and request metrics for operations and incident response.

09 · Monitoring and troubleshooting

SymptomInvestigation
401/403Check JWT claims, authorizer result, IAM signature, route permission and WAF (if used).
429 Too Many RequestsReview throttling and service quota metrics, consider client backoff.
502 Bad GatewayInspect integration response schema, Lambda logs and invocation permissions.
504 Gateway TimeoutReview backend latency, integration timeout, and retry/asynchronous alternatives.
CORS issueCheck OPTIONS/preflight and returned Access-Control-Allow-* headers.

10 · Hands-on lab: build a secured HTTP API

Step 1. Create a Lambda function implementing GET /items and POST /items with structured JSON responses.
Step 2. Create an API Gateway HTTP API and a Lambda proxy integration.
Step 3. Configure routes and a stage, then invoke the generated endpoint.
Step 4. Create a Cognito user pool or another compatible JWT issuer for an HTTP API JWT authorizer.
Step 5. Apply the authorizer to protected routes and verify both valid and invalid tokens.
Step 6. Enable access logs; exercise 4xx, 5xx, latency and metrics; clean up resources after testing.

11 · Deployment patterns and cost

Serverless API

HTTP API + Lambda + DynamoDB for request/response operations with no server fleet.

Asynchronous job API

POST → Lambda → SQS/Step Functions; return job ID and poll/status or callback later.

Existing private services

REST/HTTP API with supported VPC Link integration to private load balancer and container/service backend.

Cost management

Compare per-request gateway pricing, Lambda duration, logs, data transfer and optional WAF/security charges.
