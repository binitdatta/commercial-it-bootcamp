01 · End-to-end architecture

Users call an endpoint published through API Gateway; a Lambda proxy integration can invoke application code and return JSON. Separately, SQS, EventBridge, S3, and other event sources trigger asynchronous/background execution. The same codebase can publish versioned Lambda functions and aliases for progressive releases.

Diagram interpretation: The infographic is a conceptual overview, not a compulsory hop-by-hop network topology. CloudFront is optional, WAF attaches to supported resources (such as an API Gateway REST API stage), and asynchronous Lambda execution is triggered by supported event sources—not by treating a synchronous API integration as automatically asynchronous. Route 53 provides DNS, not an HTTP proxy.

02 · Lambda fundamentals

Function

A deployable unit comprising code, configuration, IAM execution role, runtime settings, and optional layers.

Execution environment

AWS creates and reuses isolated execution environments to handle invocations. Functions are stateless by design; persist durable state externally.

Timeout and memory

Configure per-invocation timeout, memory, and ephemeral storage. CPU allocation scales with configured memory.

Versions and aliases

Publish immutable versions and use aliases for stable stage names and controlled deployments.

04 · Java 21 / Spring Boot implementation

For Java applications, package a Lambda handler separately from a conventional embedded Tomcat server unless intentionally using a web adapter. Use a slim artifact, handle cold-start tradeoffs, and validate the selected AWS-supported runtime.

public class OrderHandler implements RequestHandler<Map<String,Object>, Map<String,Object>> {
  @Override public Map<String,Object> handleRequest(Map<String,Object> input, Context context) {
    return Map.of("statusCode", 200, "body", "{\"message\":\"ok\"}");
  }
}
// For production: validate payload, use structured JSON, inject dependencies,
// make operations idempotent, and avoid hard-coded credentials.

05 · IAM, VPC networking and secrets

  • Use least-privilege execution roles and resource-based invoke policies; do not embed AWS keys in code.
  • Use AWS Secrets Manager / SSM Parameter Store with IAM-scoped retrieval for sensitive configuration.
  • Place a function in a VPC only when it needs private network resources. VPC attachment is not required for DynamoDB or most AWS API calls.
  • When attached to a private subnet, plan internet/NAT or VPC endpoint connectivity explicitly.
  • Configure reserved concurrency where appropriate to protect shared downstream systems.

06 · Downstream service integrations

DynamoDB

Good for key-value/document access, scalable event-driven APIs and conditional writes.

Amazon RDS

Useful for relational transactions. Use connection reuse and consider RDS Proxy to reduce connection pressure.

Amazon S3

Store files and artifacts; event notifications may trigger post-processing.

SQS, SNS, EventBridge

Decouple producers/consumers, distribute events, and build retryable workflows.

08 · Packaging and deployment strategies

Step 1. Build and test the function code; select a supported runtime or container-image packaging.
Step 2. Create an IAM role with narrowly scoped downstream permissions.
Step 3. Set environment configuration, timeout, memory, and optional reserved concurrency.
Step 4. Deploy through AWS SAM, CloudFormation, CDK, Terraform or a CI/CD pipeline.
Step 5. Publish a version/alias and configure API Gateway integration or event sources.
Step 6. Test, monitor and roll back using aliases or infrastructure-as-code changes.

09 · Hands-on lab: API-triggered Lambda

Step 1. Create a Java or Python Lambda function returning a 200 response and JSON payload.
Step 2. Assign a least-privilege execution role; add a CloudWatch log group and sensible timeout.
Step 3. Create an API Gateway HTTP API; configure a Lambda proxy integration and route GET /hello.
Step 4. Deploy a stage and invoke its HTTPS URL with curl; observe payload, headers and status.
Step 5. Enable access logging on the API and structured application logs in Lambda.
Step 6. Publish a changed function version, retest, and clean up billable resources after the lab.
