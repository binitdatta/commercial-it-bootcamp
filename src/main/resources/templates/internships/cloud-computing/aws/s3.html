01 · Streaming pipeline reference architecture

This architecture shows transactional events published by multiple Spring Boot source applications into Amazon Kinesis Data Streams. Amazon Kinesis Data Firehose consumes the stream, buffers records, optionally invokes AWS Lambda to validate, enrich, and transform them, and then lands data into different Amazon S3 buckets such as raw, processed, and curated zones. Analysts then query the S3 data lake through Amazon Athena or load curated data into Amazon Redshift for higher-performance warehousing and BI reporting.

Architecture principle: Keep ingestion, delivery, transformation, storage, and analytics as clearly separated layers. That gives you operational clarity, easier troubleshooting, and flexibility to evolve each stage independently.
Important note: Firehose does not always require Lambda. Lambda is introduced when you need custom record transformation, validation, enrichment, or filtering before final delivery.

02 · End-to-end workflow

Step 1 — Publish operational events: Spring Boot applications such as order, payment, inventory, and customer services publish transactional records in JSON, Avro, or another agreed format.
Step 2 — Buffer in Kinesis Data Streams: Kinesis stores the streaming records durably in shards for real-time ingestion and replay tolerance.
Step 3 — Deliver through Firehose: Firehose consumes the stream, buffers records by time and/or size, and prepares them for managed delivery.
Step 4 — Invoke Lambda for transformation: Lambda can clean, validate, enrich, filter, or reformat each batch of records before landing.
Step 5 — Land data in S3: Firehose writes objects into raw, processed, and curated S3 buckets or prefixes based on pipeline rules.
Step 6 — Query with Athena: Athena runs SQL over S3 data using table definitions from the Glue Data Catalog.
Step 7 — Warehouse in Redshift: Curated data can also be loaded into Redshift for BI dashboards, dimensional models, and complex reporting.

04 · Amazon S3 bucket and prefix strategy

Raw zone

Store the original records with minimal change. This supports traceability, replay, audit, and backfill workflows.

Processed zone

Store cleaned or normalized records after basic validation and transformation. This is often where schema alignment begins.

Curated zone

Store analytics-ready datasets, often in partitioned columnar formats such as Parquet for Athena and Redshift loading.

Partition strategy

Use business and time partitions such as event_date=2026-10-15 or source=orders to improve analytics efficiency.

Best practice: Prefer compressed columnar formats like Parquet for processed and curated zones to reduce scan cost and improve Athena performance.

05 · Amazon Athena in the pipeline

Athena lets analysts and engineers run serverless SQL directly against S3 data. It works best when the data is structured, partitioned, and cataloged properly. Glue crawlers or explicit DDL can register tables for raw, processed, or curated datasets.

  • Great for ad hoc exploration and quick analytics
  • No infrastructure to provision
  • Charges are based on data scanned, so good file formats and partitions matter

06 · Amazon Redshift in the pipeline

Redshift is often used when the business wants a classic data warehouse experience, dimensional models, optimized BI dashboards, or higher-performance recurring analytics. Curated S3 data can be loaded into Redshift through COPY-style ingestion or other orchestration patterns.

  • Supports structured, governed analytics
  • Works well for enterprise reporting and warehouse-style transformations
  • Can complement—not replace—your S3 data lake pattern

07 · Governance, security, and observability

IAM

Use least-privilege policies for publishers, Firehose delivery roles, Lambda execution roles, Athena users, and Redshift integrations.

Encryption

Protect data in motion with TLS and data at rest with SSE-S3, SSE-KMS, or Redshift encryption controls.

Metadata and schema

Use the AWS Glue Data Catalog to register table definitions and standardize schema interpretation.

Monitoring

Use CloudWatch for metrics, logs, alarms, and delivery failure visibility across Streams, Firehose, and Lambda.

08 · What the Spring Boot source applications do

The Spring Boot services are the event producers. For example, an order service may publish order-created events, a payment service may publish payment-approved events, and an inventory service may publish stock adjustment events.

Typical producer responsibilities
- Build domain event payloads
- Add metadata (timestamp, source service, event type)
- Publish reliably to Kinesis Data Streams
- Handle retry and error paths appropriately
- Keep event schema stable and versioned
Producer design tip: Publish facts, not database tables. The event contract should represent a business event, not an arbitrary internal persistence structure.

11 · Design patterns and tradeoffs

Real-time + batch hybrid

This pattern gives you near-real-time ingestion while still landing durable datasets in S3 for downstream analytics.

Lambda transform before landing

Useful when records need cleansing or enrichment before they become part of the data lake.

Athena for flexible SQL

Best when you want rapid, serverless analysis directly on S3.

Redshift for governed BI

Best when you want a dedicated analytics warehouse with optimized dashboard performance.
