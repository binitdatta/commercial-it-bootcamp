01 · Enterprise reference architecture

The reference design shows two hybrid paths from an on-premises network into AWS: Site-to-Site VPN over the public internet using IPsec encryption, and AWS Direct Connect over a dedicated private connection. Both paths feed a Transit Gateway, which then routes to an application VPC and a shared-services / inspection VPC.

Diagram interpretation: This infographic illustrates the architecture conceptually. In an actual Transit Gateway deployment, a Site-to-Site VPN terminates as a VPN attachment to the TGW (rather than chaining a Virtual Private Gateway through the TGW), and Direct Connect integrates using a Direct Connect gateway with an associated transit virtual interface. The production, staging, and shared-services networks are separate VPCs, each requiring its own non-overlapping VPC CIDR. Validate the route tables, attachments, and BGP paths before deployment.
Architecture principle: Use Site-to-Site VPN when you need rapid deployment and encrypted connectivity over internet paths. Use Direct Connect when you need more consistent latency, higher bandwidth, and a dedicated private path for steady production traffic.
Important distinction: Direct Connect is not automatically encrypted. If workloads require encryption in transit, add MACsec where supported or overlay encryption such as IPsec at higher layers.

02 · Core concepts

Site-to-Site VPN

A managed AWS IPsec service connecting a Customer Gateway in your datacenter to AWS. VPN typically uses two tunnels for resilience and can terminate on a Transit Gateway or Virtual Private Gateway.

AWS Direct Connect

A private physical connectivity model using a dedicated circuit through a Direct Connect location or partner. It is suited for predictable throughput, private data transfer, and lower latency variation.

Transit Gateway

A regional routing hub that centralizes connectivity among VPCs and hybrid attachments. It simplifies hub-and-spoke designs and segmentation through TGW route tables and route propagation controls.

BGP route exchange

Border Gateway Protocol dynamically exchanges prefixes between your on-premises routers and AWS VPN / Direct Connect integrations. Dynamic routing reduces manual route maintenance and supports failover scenarios.

05 · Hybrid design patterns

Pattern 1 — Quick branch integration: Connect a branch office through Site-to-Site VPN to AWS for fast onboarding and secure reachability to selected VPC workloads.
Pattern 2 — Enterprise primary path: Use Direct Connect as the preferred path for production traffic, especially for high throughput, lower jitter, and private network requirements.
Pattern 3 — Shared services hub: Use a Transit Gateway and a Shared Services VPC to centralize security inspection, logging, DNS, and administrative tooling.
Pattern 4 — Branch and datacenter coexistence: Use multiple customer gateways, multiple VPNs, or multiple Direct Connect circuits where business continuity requires path diversity.
Design caution: Avoid overlapping CIDR ranges between on-premises environments and AWS VPCs. Routing ambiguity is one of the most common causes of hybrid connectivity failure.

06 · Resilience and failover

Many enterprises implement Direct Connect as the primary path and Site-to-Site VPN as the failover path. This balances performance with resiliency and can preserve business connectivity when a dedicated circuit or provider path is disrupted.

VPN resilience

Use both VPN tunnels, verify BGP timers and route preference, and test tunnel failover. Simulate loss of one tunnel and ensure traffic survives on the remaining path.

Direct Connect resilience

For stronger resilience, use redundant circuits, diverse physical paths, multiple locations or partners, and failover routing through VPN when needed.

Routing preference

BGP attributes and routing policy determine preferred versus backup paths. Document those preferences clearly to avoid unexpected route selection during incidents.

Validation

Do not assume failover works—test it. Measure recovery time, packet loss, and application behavior during path switchover.

07 · Security and governance

Segmentation

Even with hybrid links in place, use TGW route tables, VPC subnet routes, security groups, and NACLs to restrict which on-premises networks can reach which AWS services.

Encryption posture

VPN offers encryption by design. Direct Connect provides a private path but not automatic IPsec encryption; add encryption when regulatory or policy requirements demand it.

Monitoring

Use CloudWatch, Transit Gateway metrics, VPN tunnel status, Direct Connect metrics, VPC Flow Logs, and on-premises router telemetry for end-to-end visibility.

Change governance

Manage BGP advertisements, TGW route tables, and subnet route changes through controlled processes or infrastructure-as-code to reduce outage risk.

08 · Guided AWS console lab

Goal: Build a hybrid design using a Transit Gateway, one simulated Site-to-Site VPN attachment, and one Direct Connect-oriented architecture discussion path.

Step 1: Create an Application VPC (10.20.0.0/16) and a Shared Services VPC (10.30.0.0/16) with private subnets.
Step 2: Create a Transit Gateway and attach both VPCs. Add TGW routes allowing the two VPCs to communicate.
Step 3: Create a Customer Gateway object using a representative on-premises router IP. Create a Site-to-Site VPN attachment to the TGW only if you control a real or emulated compatible VPN endpoint and can establish the tunnels; otherwise stop at configuration review.
Step 4: Review the generated VPN configuration, tunnel outside IPs, and BGP ASN settings. Understand how the on-premises device would be configured in production.
Step 5: Add VPC subnet routes for on-premises prefixes to the TGW. Add reciprocal learned or configured routes on the on-premises side.
Step 6: For Direct Connect, document the intended private virtual interface, Direct Connect gateway association, and route advertisement model. In many labs this remains conceptual due to physical circuit requirements.
Step 7: If both VPN tunnels are operational, test connectivity and controlled tunnel failover. Otherwise describe the expected BGP and failover sequence without claiming functional connectivity.
Step 8: Clean up TGW attachments, VPN resources, and disposable workloads after the lab to avoid charges.

10 · Cost, performance, and operations

Site-to-Site VPN generally has lower entry cost and faster setup, but internet path variability affects latency and throughput. Direct Connect usually carries higher setup and recurring cost, but can deliver better operational stability for heavy production traffic.

Operationally, choose the simplest design that meets the requirement: branch or backup access often fits VPN, while core enterprise integration commonly justifies Direct Connect. Many mature designs use both.
