02 · Core concepts

AWS Transit Gateway

A regional routing hub that connects VPCs and supported hybrid attachments. Each VPC attachment uses subnets in selected Availability Zones; attachment-associated Transit Gateway route tables govern reachability to other attachments.

VPC Peering Connection

A private network connection between two VPCs, including cross-account and inter-Region options. It is not transitive: if VPC A peers with B and B peers with C, A cannot traverse B to reach C using those peerings.

VPC attachment

Links one VPC to a TGW using attachment subnets. Workload subnets need VPC routes toward the TGW, and the TGW needs corresponding routes back to those networks.

Routing domain

An association between a TGW attachment and exactly one TGW route table determines which routes the attachment uses to forward traffic. Propagation can add eligible attachment prefixes to selected TGW route tables.

05 · Hub-and-spoke design and segmentation

A landing-zone network architecture typically separates production, nonproduction, shared services, and inspection functions. TGW route-table association and route propagation allow different spokes to have distinct reachability policies.

1. Choose boundaries. Partition CIDR space so VPCs and connected on-premises networks do not overlap. Reserve growth space.
2. Attach VPCs. Select TGW attachment subnets across required Availability Zones; confirm TGW attachment status is available.
3. Associate each attachment. Choose the appropriate TGW route table for the attachment’s permitted destinations.
4. Enable controlled propagation. Propagate prefixes only to route tables whose consumers should see them, or configure explicit static routes.
5. Update VPC routes and firewalls. Add routes to TGW, then scope SG and NACL rules to allowed ports and principals.
Segmentation is a routing policy, not a substitute for authorization. TGW routing prevents paths from being installed; network security groups, inspection controls, and IAM govern access at other layers.

06 · Hybrid and multi-Region connectivity

On-premises connection options

A Site-to-Site VPN connects via encrypted IPsec tunnels over internet-based paths. AWS Direct Connect provides dedicated connectivity; a Direct Connect gateway can associate with a TGW subject to supported configuration and quotas. Route advertisements and return routing require deliberate design.

Transit Gateway inter-Region peering

Create a TGW peering attachment between TGWs in different AWS Regions, accept it as required, and configure static routes in relevant TGW route tables. TGW peering does not automatically propagate route entries between the peered gateways.

VPC Peering across Regions

VPC Peering also supports direct cross-Region connectivity, subject to its one-to-one, non-transitive model. Choose it when the requirement is direct connectivity rather than an expandable central routing hub.

07 · Security and operational governance

Least-privilege routing

Associate production and nonproduction attachments with separate TGW route tables. Avoid broad default propagation when environments require isolation.

Inspection VPC

For centralized filtering, design symmetric paths through inspection appliances and use TGW appliance mode where appropriate. Never assume all paths pass through the firewall without examining both directions.

IAM, RAM & accounts

Use narrowly scoped IAM privileges. AWS Resource Access Manager can share TGWs across accounts in supported configurations; govern attachment acceptance and route ownership.

Visibility

Use VPC Flow Logs, TGW Flow Logs, CloudWatch metrics and alerts, Reachability Analyzer where supported, and AWS Config / CloudTrail for traceability.

08 · Guided AWS console lab

Goal: Connect a production VPC to a shared-services VPC through a TGW, then demonstrate isolated access to a third staging VPC. Use a disposable account or sandbox with budget controls.

Step 1: Create three VPCs with non-overlapping ranges: 10.1.0.0/16, 10.2.0.0/16, and 10.3.0.0/16. Add two private subnets to each for the TGW attachments and test workloads as appropriate.
Step 2: Create a TGW in the same Region. Disable default association/propagation if you want explicit segmentation from the beginning.
Step 3: Create three VPC TGW attachments; choose one attachment subnet in each relevant AZ. Wait until all attachments report available.
Step 4: Create prod-rt and shared-rt TGW route tables. Associate production with prod-rt; shared services with shared-rt. Configure routes allowing only the intended production↔shared-services paths.
Step 5: Add subnet routes in the participating VPCs directing remote CIDRs to the TGW. Ensure reverse routes exist and workloads permit required probe ports.
Step 6: Verify connectivity between production and shared services using a test application or permitted network probe. Confirm staging is isolated without a permitted TGW route.
Step 7: Create a separate VPC peering connection between two small test VPCs. Accept it, add reciprocal subnet routes, and test direct connectivity.
Step 8: Delete test peering, TGW attachments, TGW and disposable workloads after validation to prevent ongoing charges.
Lab safety: A route by itself does not open application ports. Use tightly scoped security group rules, avoid public test workloads when not needed, and delete billable attachments after the lab.

10 · Cost, resilience and operations

TGW generally incurs per-attachment hourly and data-processing charges, with additional charges possible for VPN, Direct Connect, inter-Region transfers or other services. VPC Peering typically does not have a connection-hour charge, but applicable data-transfer charges remain.

For resilient designs, deploy TGW attachment subnets in each required AZ, test failure scenarios, manage route tables as code, audit unintended transitive paths, and monitor connection and packet-loss indicators. Prefer verified current AWS pricing and quotas over static cost estimates.

12 · Key terms and further reading

TGW: Transit Gateway. Attachment: a VPC, VPN, peering, or other supported connection to a TGW. Association: the TGW route table an attachment uses when forwarding. Propagation: adding eligible attachment routes to a TGW route table. Peering: a direct private connection between two VPCs or two TGWs, depending on the service.
