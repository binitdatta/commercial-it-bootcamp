1. Git SCM fundamentals

Git is a distributed version control system. Every clone has its own history. GitHub, GitLab and Bitbucket are remote hosting and collaboration services, not replacements for Git.

ConceptMeaning
Working treeFiles you edit on your computer.
Staging area / indexThe exact changes selected for your next commit with git add.
Local repositoryCommit history and Git metadata in the .git directory.
CommitA recorded snapshot with author, message and parent relationship.
BranchA movable reference to a sequence of commits; commonly main or feature/*.
Remote / originA named reference to another repository. origin is a convention, not a special server.
Pull requestA hosting-platform review workflow; not a core Git command.

Typical change lifecycle

Edit → git status → git add → git commit → git push → Review / merge

2. Install Git on macOS

Option A — Xcode Command Line Tools (simple default)

xcode-select --install
git --version
which git

macOS may prompt for Command Line Tools when Git is first invoked. Complete the dialog and reopen Terminal.

Option B — Homebrew

If Homebrew is already installed, use:

brew update
brew install git
git --version
which git

Homebrew commonly installs under /opt/homebrew on Apple Silicon and /usr/local on Intel. If an older Apple-provided Git is still selected, check your shell PATH and which -a git.

Validation: git --version should print an installed version. Do not rely on a particular version number; newer security fixes are desirable.

3. Install Git on Windows 10 / 11

Option A — winget (recommended when available)

Open PowerShell and run:

winget install --id Git.Git -e --source winget

Close and reopen PowerShell. Verify:

git --version
where.exe git

Option B — Official installer

Download Git for Windows from git-scm.com/downloads/win. Follow the installer; include Git in the command-line PATH. Git Bash is included and provides a Unix-like terminal.

Line endings: Configure your repository intentionally. A common Windows default is core.autocrlf=true; teams should prefer a repository-level .gitattributes file for consistent cross-platform handling.

If PowerShell says git is not recognized, start a fresh terminal first. If it still fails, verify installation and PATH rather than repeatedly reinstalling.

4. Install Git on Linux

Ubuntu / Debian

sudo apt update
sudo apt install -y git
git --version
command -v git

Distribution repositories supply versions maintained for that release. If you require newer features, follow your distribution's supported package guidance.

Fedora / RHEL family

sudo dnf install -y git
git --version
command -v git

Package manager and available versions vary by distribution and release. Use your organization's approved repositories.

5. First-time configuration

Set the identity that appears in commits. Replace the sample name and email with your own details. A hosting-service private/noreply address is acceptable when configured appropriately.

git config --global user.name "Your Name"
git config --global user.email "you@example.com"
git config --global init.defaultBranch main
git config --global core.editor "code --wait"
git config --global --list --show-origin
Editor prerequisite: The code --wait setting works only after the VS Code command-line launcher is available. Otherwise leave your existing editor or choose another installed editor.

Understand configuration scope:

--systemMachine-wide; usually requires elevated privileges.
--globalCurrent user's configuration.
--localCurrent repository only; useful for employer-specific email identity.

Inspect the effective setting with git config --show-origin --get user.email. Never put personal access tokens, passwords, or private keys in Git configuration files or commits.

6. Hands-on lab: your first repository

Goal: Build a small repository, make commits, create a branch and merge it back. Run each group of commands in a terminal.

Step 1 — Create a new local repository
mkdir git-internship-lab
cd git-internship-lab
git init -b main
printf '# Git Internship Lab\n' > README.md
git status

On Windows PowerShell, create README.md using Set-Content README.md '# Git Internship Lab' instead of printf.

Step 2 — Stage and commit
git add README.md
git diff --cached
git commit -m "docs: initialize internship repository"
git log --oneline --decorate -5
Step 3 — Create a feature branch
git switch -c feature/installation-notes
# Edit README.md to add installation notes
git status
git add README.md
git commit -m "docs: add installation notes"
git switch main
git merge feature/installation-notes
git log --oneline --graph --all
Step 4 — Examine changes before committing
git status
git diff
git diff --cached
git branch -vv
git log --oneline --graph --decorate --all
Safety: Do not run git reset --hard, git clean -fd, or force pushes until you understand how they may discard work or rewrite history.

7. Connect to GitHub with SSH or HTTPS

SSH authentication (personal development workstation)

Create a new SSH key if you do not already have a suitable one. Do not overwrite an existing key. GitHub hosts the public key only; the private key stays on your machine.

ssh-keygen -t ed25519 -C "you@example.com"
# Follow prompts; use a passphrase and a safe key-file location
# Add the contents of your PUBLIC key (.pub) to GitHub account settings
ssh -T git@github.com

Review the SSH host-key fingerprint against GitHub's official documentation before accepting a first connection. On managed workstations, follow organizational key management requirements.

HTTPS authentication

Use a supported credential manager (Git Credential Manager or your IDE integration) or a hosting provider's documented token workflow. A GitHub account password is not accepted for Git operations over HTTPS. Do not embed tokens in remote URLs.

Publish your local repository

Create an empty repository in GitHub first, without an initial README, then substitute your actual account/repository name:

git remote add origin git@github.com:YOUR-USER/git-internship-lab.git
git remote -v
git push -u origin main

To use HTTPS instead, choose the HTTPS remote URL shown by GitHub. If the remote already has an independent initial commit, do not blindly force-push; reconcile histories first.

References: Pro Git (official book) · GitHub SSH setup · Git downloads.

8. Git for Spring Boot / IntelliJ / VS Code

For the Commercial IT Bootcamp Java projects, commit source code, Maven build definitions, tests and documentation—not generated build outputs, IDE secrets, local credentials or database contents.

Example .gitignore for a Maven/Spring Boot training project:

target/
*.log
.env
.env.*
!.env.example
.idea/
*.iml
.vscode/
.DS_Store

Adjust IDE exclusions to your team's policy: shared VS Code settings may be committed if they are safe and intentional. Files already tracked by Git remain tracked even after adding them to .gitignore; review before using git rm --cached.

In IntelliJ IDEA or VS Code, open the repository folder, check the Source Control panel, make a small change, review its diff, stage it, commit and inspect the local history. CLI and IDE operations modify the same Git repository.

9. Common installation and workflow problems

SymptomLikely reason / safe next action
git: command not foundGit is missing or not on PATH. Verify with which git / where.exe git and reopen the terminal.
Author identity unknownSet user.name and user.email; verify scope.
Permission denied (publickey)Check the GitHub account's public key, selected SSH identity and remote URL. Do not share your private key.
remote origin already existsInspect git remote -v; update intentionally with git remote set-url origin URL if needed.
rejected (non-fast-forward)The remote has commits you lack. Fetch and inspect; reconcile or rebase as team policy requires. Avoid force-push.
Merge conflictOpen conflicted files, resolve markers, test, then stage and complete the merge. Check git status throughout.
Unexpected files stagedReview git diff --cached --name-only; unstage selectively with git restore --staged FILE.
