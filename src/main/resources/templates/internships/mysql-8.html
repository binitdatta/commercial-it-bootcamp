1. Understand the MySQL architecture

ComponentRole in a commercial application
MySQL Server (mysqld)Database service that stores data, executes SQL statements, manages transactions and enforces access controls.
MySQL CLI (mysql)Command-line client that connects to the server and executes SQL; installing only the client does not install a database server.
MySQL WorkbenchOptional graphical SQL editor and administration tool; its version/OS support should be checked separately from the server.
InnoDBDefault transactional storage engine with ACID transactions, foreign keys and crash recovery.
Connector/JJDBC driver that lets Spring Boot connect to MySQL over TCP (typically port 3306).
Schema / databaseLogical namespace for application tables, views and other database objects. CREATE DATABASE creates a schema.
Architecture: Spring Boot API → JDBC / Spring Data JPA → MySQL Connector/J → local MySQL Server → InnoDB tables. MySQL Workbench is an optional client, not part of the runtime application path.

2. Select the correct MySQL 8 release

MySQL 8.0 and MySQL 8.4 LTS both belong to the MySQL 8 family, but they are different release series. For new training installations, prefer a current supported MySQL 8.4 LTS patch unless your existing application explicitly requires 8.0. Always confirm compatibility with the project's MySQL version and JDBC driver.

Choose MySQL Community Server (not Enterprise Edition), the correct operating system, CPU architecture and supported installer. Prefer Oracle's official installer or operating-system packages that clearly identify the MySQL version.

MySQL Community Server downloads ↗ · MySQL 8.4 Reference Manual ↗ · MySQL 8.0 Reference Manual ↗

Version check: Package-manager defaults change over time and across Linux distributions. Do not assume mysql-server or brew install mysql installs the same version on every machine. Always verify with SELECT VERSION();.

3. macOS — Apple Silicon and Intel

macOS · recommended for a predictable MySQL 8 installation

Option A · Official MySQL Community DMG package

1
Open the official Community Server download page. Choose macOS, a supported 8.x release and an architecture that matches your Mac (ARM64 for Apple Silicon, x86_64 for Intel).
2
Download the DMG archive, open the included installer package and follow the installation wizard. Set a strong MySQL root password when prompted; save it in a password manager.
3
Start the MySQL service using the installed MySQL preference pane or vendor-supplied startup tooling. If the command-line client is not on PATH, use its typical Oracle-package location:
/usr/local/mysql/bin/mysql --version
/usr/local/mysql/bin/mysql -u root -p
Enter the root password interactively when asked.
4
If needed, expose the Oracle-package CLI in zsh (without changing any existing Java configuration):
echo 'export PATH="/usr/local/mysql/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc
mysql --version

Option B · Homebrew, when an appropriate version-pinned formula is available

Check the actual formula and supported version on your machine before installing. Use a version-pinned formula only if it is currently offered; the unpinned mysql formula may install a newer major release.

brew search mysql
brew info mysql@8.4
# Only if the formula is available and suitable:
brew install mysql@8.4
brew services start mysql@8.4
brew --prefix mysql@8.4

Versioned Homebrew formulae may be keg-only. Follow the brew info output to add the correct bin directory to your PATH. Follow its printed initialization and root-login instructions; do not assume a default password.

Choose one server installation method for a simple internship environment. Installing an Oracle DMG server and a Homebrew server simultaneously can cause port 3306 and data-directory conflicts.

4. Windows 10 / 11 installation

Windows · MySQL Installer or official MSI package

1
Download a Windows Community Server installer from Oracle MySQL Downloads. Where offered for your chosen release, MySQL Installer can also coordinate server and Workbench installation. Installer availability differs between the 8.0 and 8.4 series.
2
Install MySQL Server and keep the installation folder documented (for example, C:\Program Files\MySQL\MySQL Server 8.4\). In the configuration wizard, choose a development machine profile when available and use TCP/IP port 3306 unless it is already occupied.
3
Use a supported password-based authentication configuration, assign a strong root password, and register MySQL as a Windows Service so it can be started and stopped with the Services console. Keep the server bound to local access for training.
4
Open PowerShell. Update this example path to the directory you actually installed:
& 'C:\Program Files\MySQL\MySQL Server 8.4\bin\mysql.exe' --version
& 'C:\Program Files\MySQL\MySQL Server 8.4\bin\mysql.exe' -h 127.0.0.1 -u root -p
5
For convenient command-line access, add the installed MySQL bin directory to the system or user Path via Environment Variables, then reopen PowerShell and run mysql --version.

Service verification

# PowerShell (service name may differ)
Get-Service *mysql*
# Start only the service name displayed on your machine:
Start-Service -Name MySQL84
Workbench is a separate graphical client. Install a supported edition if you want a visual SQL editor; select host 127.0.0.1, port 3306, and the application account you create in the security lab below.

5. Linux — Ubuntu, Debian and Fedora

Linux · distribution packages or Oracle MySQL repository

Ubuntu / Debian · Inspect the package candidate first

sudo apt update
apt-cache policy mysql-server
# Read the candidate version before installing
sudo apt install mysql-server
sudo systemctl enable --now mysql
sudo systemctl status mysql --no-pager

Package availability and exact MySQL version vary by release and repository. Some systems ship a different major version or MariaDB via alternate packages. If you require an exact Oracle MySQL 8 release, use the official MySQL APT repository configuration and follow its documentation for selecting the right release before installation.

On some Debian/Ubuntu setups, the administrative root account uses local socket authentication. You may initially administer MySQL using sudo mysql rather than a root password. Do not change this to password authentication solely to make a tutorial command work.

Fedora / RPM-based systems

Check available packages and repositories first. Fedora and enterprise RPM-based distributions may offer MariaDB instead of Oracle MySQL by default. For exact MySQL 8, use the matching official MySQL Yum repository instructions for your supported distribution.

sudo dnf info mysql-server
# Proceed only after verifying the package provider/version:
sudo dnf install mysql-server
sudo systemctl enable --now mysqld
sudo systemctl status mysqld --no-pager

On some distributions the service is named mysql instead of mysqld. Use systemctl list-unit-files '*mysql*' '*mysqld*' to identify your actual unit.

Verify the daemon and connect

mysql --version
sudo ss -ltnp | grep ':3306'
# Use either the configured root password or local socket login:
mysql -u root -p
# On socket-authenticated installations, instead use: sudo mysql
Avoid opening inbound port 3306 to the public internet. For this lab, prefer local connections only, or use an explicitly secured tunnel if remote administration is later required.

6. Secure the server and provision an application user

Log in as a MySQL administrator using the method appropriate to your OS. On installations supporting it, run mysql_secure_installation and review its prompts for anonymous accounts, remote root login, test databases and password policy. Behavior depends on the installer and installed version.

Never run a Spring Boot application as root. Instead, create a dedicated local account and a training schema. Run the following SQL in an administrative MySQL session:

CREATE DATABASE IF NOT EXISTS internship_lab
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_0900_ai_ci;

CREATE USER IF NOT EXISTS 'intern_app'@'localhost'
  IDENTIFIED BY 'REPLACE_WITH_UNIQUE_STRONG_PASSWORD';

GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER,
      INDEX, DROP, REFERENCES
ON internship_lab.* TO 'intern_app'@'localhost';

SHOW GRANTS FOR 'intern_app'@'localhost';

The privileges above support local development and schema exercises. In production, manage schema changes through an authorized migration identity and grant the application only the DML privileges it needs.

Security note: Replace the example password before executing. Do not commit passwords to Git or copy them into public screenshots. If connecting over TCP to 127.0.0.1, test that the account's host matching works on your installation; use a deliberately scoped 'intern_app'@'127.0.0.1' account if required rather than an unrestricted '%' account.

Test the least-privilege connection

mysql -h localhost -u intern_app -p internship_lab
SELECT CURRENT_USER(), DATABASE(), VERSION();

7. Hands-on lab — SQL, keys and ACID transactions

Connect as intern_app to internship_lab. Execute these statements in order. Observe the effect of a rollback and a committed transfer.

USE internship_lab;

CREATE TABLE IF NOT EXISTS customer (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  full_name VARCHAR(120) NOT NULL,
  email VARCHAR(255) NOT NULL UNIQUE,
  created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB;

CREATE TABLE IF NOT EXISTS account (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  customer_id BIGINT NOT NULL,
  balance DECIMAL(12,2) NOT NULL DEFAULT 0.00,
  CONSTRAINT fk_account_customer FOREIGN KEY (customer_id)
    REFERENCES customer(id)
) ENGINE=InnoDB;

INSERT INTO customer (full_name, email)
VALUES ('Alex Morgan', 'alex@example.test'),
       ('Taylor Reed', 'taylor@example.test');

INSERT INTO account (customer_id, balance)
SELECT id, 250.00 FROM customer WHERE email='alex@example.test';
INSERT INTO account (customer_id, balance)
SELECT id, 100.00 FROM customer WHERE email='taylor@example.test';

SELECT c.full_name, a.balance
FROM customer c JOIN account a ON a.customer_id=c.id;

START TRANSACTION;
UPDATE account SET balance=balance-25.00 WHERE customer_id=1;
UPDATE account SET balance=balance+25.00 WHERE customer_id=2;
ROLLBACK;

SELECT * FROM account;

START TRANSACTION;
UPDATE account SET balance=balance-25.00 WHERE customer_id=1;
UPDATE account SET balance=balance+25.00 WHERE customer_id=2;
COMMIT;

SELECT * FROM account;
Exercise assumption: The transfer uses IDs 1 and 2, which normally appear in a brand-new schema. If you already have records, query the generated customer IDs first and substitute the correct values. Re-running the inserts without clearing the database may violate the unique-email constraint.

Concepts to explain to a reviewer

  • Why money balances use DECIMAL instead of floating-point types.
  • What primary keys, unique constraints and foreign keys protect.
  • Why ROLLBACK undoes uncommitted DML and COMMIT makes changes durable.
  • Why a SQL client can be closed without stopping the MySQL database service.

8. Connect Spring Boot 4 / Java 21 to MySQL 8

Your Commercial IT Bootcamp already uses MySQL and Spring Data JPA. For a new training application, include Spring Data JPA and the MySQL Connector/J runtime driver. With Spring Boot dependency management, usually omit the driver's explicit version.

<dependency>
  <groupId>org.springframework.boot</groupId>
  <artifactId>spring-boot-starter-data-jpa</artifactId>
</dependency>
<dependency>
  <groupId>com.mysql</groupId>
  <artifactId>mysql-connector-j</artifactId>
  <scope>runtime</scope>
</dependency>

Example development-only application.yml, with the password supplied through an environment variable:

spring:
  datasource:
    url: jdbc:mysql://localhost:3306/internship_lab
    username: intern_app
    password: ${DB_PASSWORD}
  jpa:
    hibernate:
      ddl-auto: validate
    open-in-view: false

Use ddl-auto: validate once your tables are established and JPA entities match the schema; without entities or for initial experimental schema creation, your bootstrap process may differ. For commercial projects, use database migrations such as Flyway or Liquibase instead of relying on automatic schema creation.

Connection diagnostics: A JDBC URL describes where the server listens; the driver is a Java dependency; a database user grants access. Each is separate, and each can fail independently.

9. Troubleshooting and operational checks

SymptomLikely cause / check
mysql: command not foundClient not installed or the installation's bin directory is missing from PATH.
ERROR 2002 / connection refusedServer stopped; incorrect socket, host or port; confirm the service and listening address.
ERROR 1045 Access deniedIncorrect user/password or host-specific MySQL account match. Check the user definition and chosen auth method.
Port 3306 already occupiedAnother MySQL/MariaDB or container instance may be running. Identify it before changing ports or stopping services.
Workbench cannot connectCheck the server independently with the CLI; verify host, port, credentials and SSL/TLS settings.
Spring Boot JDBC failureCheck mysql-connector-j, schema name, environment variables, account grants and MySQL service health.
Wrong version installedSELECT VERSION(); reports the connected server, not just the client's version; inspect your package or service selection.

Useful read-only diagnostics

mysql --version
mysql -h localhost -u intern_app -p -e "SELECT VERSION(), CURRENT_USER();"
# In an administrative SQL session:
SHOW VARIABLES LIKE 'port';
SHOW VARIABLES LIKE 'bind_address';
SHOW DATABASES;

10. Internship submission and knowledge check

Demonstrate your environment, not merely an installation screenshot. Provide redacted evidence showing the server version, a successful non-root connection, the created schema and tables, and a rollback/commit exercise.

Short oral assessment

  1. What happens when the SQL client exits? Does the server stop?
  2. How is 'intern_app'@'localhost' different from a remote account?
  3. Why must a Spring Boot application avoid using the MySQL root account?
  4. What is the difference between a database schema, a table, a primary key and a foreign key?
  5. How does InnoDB support an atomic multi-statement transaction?
