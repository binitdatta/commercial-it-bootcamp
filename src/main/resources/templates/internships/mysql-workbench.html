1. Understand MySQL Workbench architecture

MySQL Workbench is a graphical database client and modeling/administration tool. It is not a MySQL database server. Your earlier MySQL 8 lesson supplies the database service.

ComponentResponsibility
WorkbenchSQL editor, database navigator, query results, data modeling and administration UI.
MySQL ServerStores data, authenticates users, executes transactions and listens on configured network/socket endpoints.
TCP/IPLocal connection commonly uses 127.0.0.1:3306 when MySQL is configured for the default port.
Application JDBC clientSpring Boot connects independently of Workbench using MySQL Connector/J.
Workbench needs a compatible running server to browse/query data. Installing Workbench alone will not create mysqld or start port 3306.

2. Choose the correct version and platform

Download the current MySQL Workbench Community build offered for your supported OS at Oracle's official Workbench downloads.

Compatibility note: Oracle documents Workbench 8.0 as developed and tested with MySQL Server 8.0. It can connect to MySQL 8.4 and later servers, but some features may not work. Check the official manual and supported platforms for your exact OS/server combination.

Choose the appropriate architecture and installer. Some Linux distributions and newer operating-system versions may not have a matching official binary: do not force an unsupported package. Prefer a supported host or compatible client.

3. Install on macOS (Apple Silicon / Intel)

  1. Visit MySQL Workbench Downloads.
  2. Select the macOS build supported for your OS version and architecture; check the release's platform compatibility.
  3. Download the official DMG, open it and drag MySQL Workbench into Applications (follow installer prompts if supplied).
  4. Launch Workbench from Applications and grant permissions required by macOS.
  5. Verify that your MySQL Server is running separately before creating a connection.
uname -m
# arm64 (Apple Silicon) or x86_64 (Intel)
mysql --version
# CLI availability is optional for Workbench, but useful for troubleshooting.
lsof -nP -iTCP:3306 -sTCP:LISTEN
If macOS blocks opening an app, confirm it came from Oracle's official download site and use the approved macOS Privacy & Security workflow. Do not disable system protections globally.

4. Install on Windows 10/11

  1. Download MySQL Workbench from Oracle, selecting the supported Windows package.
  2. Run the installer and follow its prerequisites and setup prompts. The MySQL Installer may also offer Workbench alongside Server depending on the chosen MySQL distribution.
  3. Open MySQL Workbench from the Start menu.
  4. Check that the MySQL Server Windows service is running; Workbench does not start a missing server installation.
# PowerShell
Get-Service *mysql*
Test-NetConnection -ComputerName 127.0.0.1 -Port 3306

For an absent service, return to the MySQL Server lesson and install/configure Server separately.

5. Install on Linux (Ubuntu / Debian / Fedora)

  1. Check Oracle's support matrix for your exact distribution release and architecture.
  2. Download an appropriate official DEB/RPM package or configure Oracle's supported MySQL software repository.
  3. Install using your package manager, letting it resolve required libraries. Package names and availability vary by release.
  4. Launch via the desktop menu or mysql-workbench where that executable is installed.
# Ubuntu / Debian: inspect available package metadata
apt-cache policy mysql-workbench-community
# Fedora / RHEL-family: inspect repository availability
dnf info mysql-workbench-community
# Install only after confirming an appropriate supported package.
Do not assume apt install mysql-workbench works on all distributions. If Oracle offers no compatible package for your Linux release, choose a supported environment rather than mixing incompatible repositories.

6. Create and test a local database connection

  1. Launch Workbench and select the + button next to MySQL Connections.
  2. Connection name: Bootcamp Local MySQL 8.
  3. Connection method: Standard (TCP/IP).
  4. Hostname: 127.0.0.1; Port: 3306 unless configured otherwise.
  5. Username: use an existing development user with least-required privileges, rather than the root account for daily work.
  6. Choose Test Connection; provide the password through the prompt. Save credentials only if allowed by your workstation policy.
  7. Open the connection and inspect the Schemas navigator.
Security: Never put a real password into lesson material, screenshots, README files, Git repositories, connection URLs, or shared training outputs. Never expose MySQL port 3306 publicly for this local lab.
-- Run in a Workbench SQL tab after connecting.
SELECT VERSION() AS mysql_version,
       CURRENT_USER() AS authenticated_account,
       DATABASE() AS selected_schema;

7. Hands-on SQL Editor lab

Run these statements in the SQL Editor. The account needs CREATE rights for the practice schema; ask the lab administrator for a scoped account if necessary.

CREATE DATABASE IF NOT EXISTS internship_lab;
USE internship_lab;

CREATE TABLE IF NOT EXISTS departments (
    department_id BIGINT PRIMARY KEY AUTO_INCREMENT,
    department_name VARCHAR(80) NOT NULL UNIQUE
) ENGINE=InnoDB;

CREATE TABLE IF NOT EXISTS interns (
    intern_id BIGINT PRIMARY KEY AUTO_INCREMENT,
    intern_name VARCHAR(100) NOT NULL,
    department_id BIGINT NOT NULL,
    CONSTRAINT fk_intern_department FOREIGN KEY (department_id)
        REFERENCES departments(department_id)
) ENGINE=InnoDB;

INSERT INTO departments (department_name) VALUES ('Engineering');
INSERT INTO interns (intern_name, department_id)
SELECT 'Alex', department_id FROM departments
WHERE department_name = 'Engineering';

SELECT i.intern_id, i.intern_name, d.department_name
FROM interns i JOIN departments d
  ON i.department_id = d.department_id;

START TRANSACTION;
UPDATE interns SET intern_name = 'Alex Morgan'
WHERE intern_name = 'Alex';
ROLLBACK;

SELECT * FROM interns;

The final query should still show Alex after rollback. This demonstrates transactional behavior, an InnoDB relationship and a join. Re-running the INSERT statements duplicates the sample data; use a fresh schema or clean up when repeating the lab.

8. Inspect schemas and create an ER diagram

  1. Refresh the Schemas sidebar and expand internship_lab.
  2. Inspect Tables → interns / departments, columns, primary keys, indexes and foreign-key details.
  3. Open Database → Reverse Engineer (menu availability may vary by release).
  4. Select the connection and practice schema, then follow the wizard to produce a model.
  5. Inspect the relationship between interns.department_id and departments.department_id.
  6. Save the model and export a diagram if supported by your installed version.

Explain the entities, cardinality, primary key, foreign key and why the database—not the UI—enforces referential integrity.

9. Data export, import and safe operations

Use Server → Data Export (where supported) to export the internship_lab schema; select appropriate structure and data options. Test import into a disposable schema rather than overwriting the source.

# Alternative: command-line logical export
mysqldump -u lab_user -p internship_lab > internship_lab.sql

# Restore only into a separate empty practice schema after review.
# Never import an untrusted SQL dump into a sensitive database.
The export UI and server administration capabilities depend on platform/version/privileges. Workbench is not a replacement for a tested production backup and recovery policy.

Production principle: use separate read-only and administration credentials; avoid root for routine development; confirm the target host/schema before any DDL or DELETE action.
