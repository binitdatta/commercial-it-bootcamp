Why databases exist

Application memory disappears; business records must not

Orders, customers, payments and inventory must survive restarts, support concurrent users, enforce integrity and remain queryable years later. A relational database is not merely a file store; it is a transactional consistency engine.

Core SQL

SQL describes the result you want

READ
SELECT o.order_id, o.status, c.email
FROM orders o
JOIN customer c ON c.customer_id = o.customer_id
WHERE o.status = 'PAID'
ORDER BY o.order_id DESC;
WRITE
UPDATE orders
SET status = 'CANCELLED'
WHERE order_id = 98765
  AND status IN ('CREATED','PAID');

Transactions and ACID

Related changes should succeed together or fail together

AAtomicityAll-or-nothing unit of work
CConsistencyRules remain valid before and after
IIsolationConcurrent work does not corrupt results
DDurabilityCommitted data survives failure
Example: Creating an order header without its order lines because the second insert failed is a partial business transaction. Transaction boundaries prevent this class of corruption.
Indexes and performance

Indexes accelerate reads but are not free

Indexes help when

  • Filtering frequently by selected columns
  • Joining on keys
  • Supporting ordered access patterns
  • Enforcing uniqueness

Indexes cost

  • Storage
  • Additional work on INSERT/UPDATE/DELETE
  • Maintenance and statistics
  • Complexity if added without query evidence

Hands-on lab

Inspect the reference schema and answer business questions

  1. Open the project's SQL schema and identify primary and foreign keys.
  2. Find the tables that represent orders and order lines.
  3. Write a SELECT that lists orders for one customer.
  4. Write a JOIN that returns order plus customer information.
  5. Identify one column that deserves an index and explain the access pattern.
  6. Explain what must be in one transaction when an order is created.
Knowledge check

Can you reason beyond CRUD?

1. Why use a foreign key?

To express and optionally enforce a valid relationship between rows.

2. Why can an index hurt writes?

The database must maintain index structures when indexed data changes.

3. What does atomicity protect?

It prevents a multi-step transaction from being only partially committed.

4. 10,000 rows returned but only 20 needed?

Filter and paginate at the database/API boundary rather than loading everything.
