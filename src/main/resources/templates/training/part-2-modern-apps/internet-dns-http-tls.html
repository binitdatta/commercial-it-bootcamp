Internet mental model

The Internet is a network of networks

Your laptop does not send a magical request directly to a server. Data is divided into packets and forwarded across multiple network devices and administrative domains until it reaches the destination network.

COMMON FAILURE
“The application works by IP but not by hostname.”

That strongly points you toward name resolution, DNS records, cached values, split-horizon DNS or certificate/host-name configuration rather than application business logic.

Transport and ports

The IP address identifies the host; the port identifies the listening service

80HTTP
443HTTPS
22SSH
3306MySQL default
5432PostgreSQL default
8080/8081Common development app ports

For traditional HTTP/1.1 and HTTP/2 over TCP, the client establishes a TCP connection before application data flows. TCP provides ordered, reliable byte delivery. Modern HTTP/3 uses QUIC over UDP, but the engineering mental model remains: transport connectivity must exist before application exchange succeeds.

Transport Layer Security

HTTPS = HTTP carried inside a TLS-protected connection

🔒ConfidentialityObservers should not be able to read application data in transit.
✓IntegrityTampering with protected traffic is detectable.
🪪Server authenticationThe certificate chain and hostname help the client validate the server it reached.
ClientHelloCapabilities + key material
→
ServerHello + certificateServer identity + negotiated parameters
→
Certificate validationTrust chain, validity, hostname
→
Session keys establishedEncrypted application data
Important: TLS does not make an application “secure.” It protects transport. Authorization flaws, SQL injection, weak passwords, insecure business logic and leaked secrets can still exist above TLS.

Knowledge check

Can you reason across the layers?

1. What problem does DNS solve?

It maps human-usable names to network addressing information.

2. Why can HTTPS fail even when DNS works?

The host may be reachable but TLS certificate, protocol or listener configuration can still be wrong.

3. What does HTTP 200 tell you?

The HTTP request succeeded at the protocol/application level; it does not prove every business operation inside the page is healthy.

4. What does port 443 usually indicate?

An HTTPS listener, although ports are conventions rather than magical protocol guarantees.

6TLS protects transitNot business logic.
