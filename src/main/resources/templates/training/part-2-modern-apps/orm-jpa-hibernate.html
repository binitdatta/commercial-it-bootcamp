Terminology

ORM, JPA and Hibernate are related but not synonyms

ORMObject-Relational Mapping—the general technique of mapping object models to relational data.
JPA / Jakarta PersistenceThe Java persistence specification/API: annotations, EntityManager semantics and contracts.
HibernateA widely used implementation of Jakarta Persistence with additional capabilities.
Spring Data JPAA Spring abstraction that can generate repository implementations on top of JPA.
Entity mapping

A Java class becomes persistence metadata

ILLUSTRATIVE ENTITY
@Entity
@Table(name = "orders")
public class Order {
    @Id
    @GeneratedValue
    private Long id;

    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "customer_id")
    private Customer customer;

    @Enumerated(EnumType.STRING)
    private OrderStatus status;
}

Annotations describe mapping. They do not remove the relational model underneath.

Relationships

Object references must map to foreign keys

@ManyToOneMany orders belong to one customer.
@OneToManyOne order contains many order lines.
@OneToOneOne row maps to at most one related row.
@ManyToManyOften requires a join table; use carefully when the relationship has its own data.
Commercial rule: Learn which side owns the foreign key and which cascade operations are safe. Incorrect cascade settings can delete or create much more data than intended.

SERVICE BOUNDARY
@Transactional
public void cancelOrder(Long id) {
    Order order = repository.findById(id).orElseThrow();
    policy.checkCancellationAllowed(order);
    order.setStatus(OrderStatus.CANCELLED);
    // Dirty checking can persist the changed state at flush/commit.
}
Fetching

Lazy vs. eager loading is an architectural choice

Lazy loading

  • Defers related data until accessed
  • Can avoid unnecessary reads
  • Can trigger surprise queries later
  • May fail outside an open persistence context

Eager loading

  • Loads relationships immediately
  • Can simplify some use cases
  • Can over-fetch large object graphs
  • Should not be a default escape hatch
Classic failure mode

The N+1 query problem

1 queryLoad 100 orders
+
100 queriesLazy-load each order's customer
=
101 round tripsCorrect result, poor performance

Fixes may include fetch joins, entity graphs, projections or query-specific DTOs. The correct choice depends on the use case.

Spring Data JPA

Repositories remove boilerplate, not responsibility

REPOSITORY
public interface OrderRepository extends JpaRepository<Order, Long> {
    List<Order> findByCustomerIdAndStatus(Long customerId,
                                          OrderStatus status);
}
Core idea: Convenient repository methods are excellent for straightforward access. Complex reporting, bulk operations or performance-sensitive queries may need explicit JPQL, native SQL or purpose-built read models.

Anti-patterns

ORM can hide expensive or dangerous behavior

N+1 queriesLooping across relationships triggers many SQL statements.
Entity leakageReturning persistence entities directly as external API contracts couples layers.
Wrong cascadesPersist/delete propagates farther than the business operation intended.
Huge object graphsEager relationships load unnecessary data.
Long transactionsHolding DB resources while calling remote services increases contention.
Ignoring SQLGenerated SQL still determines production behavior.
Hands-on lab

Map the e-commerce persistence layer

  1. Find one @Entity in the project and identify its table and primary key.
  2. Find a relationship annotation and identify the corresponding foreign key.
  3. Locate a repository interface and one query method.
  4. Trace the service method that invokes the repository.
  5. Enable SQL logging locally and observe SQL for one page/request.
  6. Explain whether the API should return the entity directly or a DTO—and why.
Knowledge check

Can you see through the abstraction?

ORM vs. JPA?

ORM is the mapping technique; JPA/Jakarta Persistence defines Java persistence contracts.

JPA vs. Hibernate?

JPA is the specification/API; Hibernate is an implementation.

What causes N+1?

Repeated relationship loading after an initial collection query.

Why use @Transactional?

To define a consistent database unit of work around a business operation.
