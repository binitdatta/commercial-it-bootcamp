Spring Boot mental model

Boot removes setup ceremony; it does not remove architecture

Starter dependenciesCurated dependency sets.
Auto-configurationConfigures infrastructure from classpath + properties.
Embedded serverRun application directly without external app server.
Externalized configYAML/properties/environment variables.
ActuatorProduction health and management endpoints.
ConventionSensible defaults you can override deliberately.

Controllers

Controllers translate HTTP into application calls

@GetMappingRead/render resource.
@PostMappingCreate/submit action.
@PathVariableIdentity from URL path.
@RequestParamFilter/paging/options from query string.
@RequestBodyDeserialize JSON payload.
@ValidTrigger bean validation.
ModelData exposed to Thymeleaf view.
ResponseEntityExplicit REST status/headers/body.
MVC UI vs REST API

Same framework, different response style

@Controller + Thymeleaf

Returns a logical view name and model. Server renders HTML.

@RestController

Returns objects that are serialized into JSON or another response representation.

Request binding and validation

Treat all external input as untrusted

REST ENDPOINT
@PostMapping("/api/orders")
public ResponseEntity<OrderResponse> create(@Valid @RequestBody CreateOrderRequest request) {
    OrderResponse created = orderService.create(request);
    return ResponseEntity.status(HttpStatus.CREATED).body(created);
}

Validation protects shape and simple constraints. Business rules still belong in the application/domain service layer.

Exception translation

Do not leak stack traces or database exceptions into API contracts

Controller adviceMaps known application exceptions into stable HTTP responses.
Business exceptionPreserves domain meaning such as “order cannot be cancelled”.
System exceptionLogged with correlation/context; client receives safe generic error.
Configuration

Configuration belongs outside compiled code

application.ymlDefaults and structured configuration.
Environment variablesDeployment-specific values and secrets references.
ProfilesEnvironment-specific configuration where appropriate.
@ConfigurationPropertiesType-safe grouped application settings.
Never hard-code secretsUse a secret manager/injected secret.
Fail fastValidate required configuration at startup.
Layered application design

Keep transport, business and persistence concerns separate

Controller / RESTHTTP routing, binding, status codes, view/API contract.
ServiceBusiness use case and transaction orchestration.
RepositoryPersistence access.
Entity / DTOPersistence model versus external contract—do not assume they are the same thing.

Knowledge check

Can you reason about the web layer?

Boot vs Spring Framework?

Boot adds convention, auto-configuration, starters and operational defaults on top of Spring Framework.

Controller responsibility?

Translate HTTP into application calls and translate results back to HTTP/view responses.

Why DTOs?

External contracts and persistence entities evolve for different reasons.

Why centralized error handling?

Stable, consistent responses and less duplicated translation logic.

Lesson recap

Six things to remember

1Boot reduces ceremonyArchitecture still matters.
2MVC has a front controllerRequests are dispatched.
3Controllers stay thinBusiness logic belongs deeper.
4Input is untrustedBind + validate deliberately.
5Contracts are explicitDTOs and status codes matter.
6Production is a featureOperate what you build.
Career perspective

Good Spring engineers can explain the request path without saying “the framework handles it”

Framework fluency means understanding where control enters your code, where business rules live, where persistence begins and where cross-cutting behavior is inserted.
