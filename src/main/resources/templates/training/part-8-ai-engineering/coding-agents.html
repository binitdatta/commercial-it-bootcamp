AI Coding Agents

Learn how coding agents inspect repositories, plan changes, edit files, run tests and collaborate with developers inside software-engineering controls.

Learning objectives

By the end of this lesson, you should be able to

Explain the architecture

Use accurate AI terminology and place probabilistic model behavior inside normal enterprise application boundaries.

Separate AI from authority

Identify what the model may interpret or generate versus what deterministic systems must authorize and execute.

Recognize failure modes

Reason about hallucination, data exposure, tool misuse, unreliable automation, cost and operational failure.

Design a controlled implementation

Connect AI components to IAM, APIs, data, observability, testing and human governance.

Start with the engineering problem

AI coding assistants can generate large amounts of code quickly, but speed without repository context, testing and review can multiply defects just as quickly.

The durable skill is not memorizing model brands. It is knowing where probabilistic AI belongs, where it does not belong, and how to surround it with mature software-engineering controls.

Commercial principle: AI should increase the capability of an enterprise system without weakening identity, authorization, data integrity, auditability or operational control.
Core concepts

Vocabulary that matters in production

Repository Context
Source files, build configuration, tests, conventions and architecture that constrain a correct change.
Agent Plan
A proposed sequence of code-reading, modification and validation steps.
Tool Access
File reads/writes, shell commands, tests, static analysis, Git and documentation lookup.
Diff
The concrete code change that humans and automated systems can review.
Verification Loop
Edit → compile/test → inspect failure → revise until acceptance criteria are met.
Developer Accountability
Humans remain responsible for architecture, security, correctness and what is ultimately merged.
End-to-end flow

Follow one request through the architecture

1Understand task

Read issue, acceptance criteria and relevant repository documentation.

2Inspect code

Locate affected modules, contracts, tests, security boundaries and dependencies.

3Plan change

Describe intended modifications before editing broad areas of the repository.

4Implement incrementally

Make focused changes aligned to existing architecture and conventions.

5Run verification

Compile, execute tests, lint, scan and inspect runtime behavior.

6Review diff

Check security, data handling, edge cases, maintainability and unintended changes.

7Commit through normal flow

Use branch protection, pull request review and CI/CD rather than bypassing governance.

Commercial scenario

Move from demo thinking to enterprise thinking

A coding agent is asked to add an order-search endpoint. A weak approach invents new patterns. A strong approach first finds existing controllers, service methods, security conventions, DTOs and tests, then implements the smallest consistent change.

Identity
Who is asking, what organization/tenant are they in, and what are they permitted to do?
Authority
Which deterministic service owns the business fact or action?
Evidence
What logs, traces, retrieved sources, tool results and policy decisions prove what happened?
Reference application

Connect AI to the Bootcamp Spring Boot platform

Use the Bootcamp repository itself: ask an agent to trace Browser → Controller → Service → Repository for an existing feature before allowing it to add a new one.

Keycloak
Identity, authentication and trusted claims.
Spring Security
Deterministic access enforcement at application/API boundaries.
Services / APIs
Authoritative business operations exposed as governed capabilities.
MySQL
Transactional state remains in the system of record.
Production controls

What surrounds the model

IAM & policy
SSO, roles/attributes, tenant boundaries and purpose-aware authorization.
Evaluation
Representative test sets for quality, safety, groundedness and tool correctness.
Observability
Trace model calls, retrieval, tools, latency, cost, errors and decisions.
Human governance
Approval and accountability for consequential actions and exceptions.
Common failure modes

Where AI systems fail when engineering discipline is missing

Accepting code because it compiles

Compilation proves syntax and typing, not policy, security or business correctness.

Broad unattended edits

The agent changes unrelated files and creates hidden maintenance cost.

Secrets in prompts or context

Credentials or sensitive source data are copied into external services without approval.

Skipping code review

AI-generated changes bypass the same governance required for human-authored code.

Hands-on lab

Apply the concept to the reference system

Create a coding-agent task for one small Bootcamp enhancement. Write repository context, constraints, files to inspect, acceptance criteria, tests to run, forbidden actions and the expected PR review checklist.

Deliverable: Produce a one-page implementation design with architecture, trust boundaries, allowed capabilities, validation, failure handling, observability and acceptance criteria.
Knowledge check

Can you defend the design?

  1. Which component owns the authoritative business fact?
  2. What can the model decide, and what must deterministic policy decide?
  3. How is user identity carried into retrieval and tool execution?
  4. What failure could produce a fluent but unsafe result?
  5. How would you test this before production?
  6. What evidence would an operator or auditor need after an incident?
Lesson recap

Five things to remember

1. Agents need repository context.
2. Planning precedes broad edits.
3. Verification is mandatory.
4. AI code still goes through PR governance.
5. Humans own the merged outcome.
Career perspective

AI-era engineers still need strong software-engineering foundations

The engineer who understands IAM, APIs, data, distributed systems, observability, testing and business workflows can use AI far more effectively than someone who knows prompting alone. The AI layer magnifies both good architecture and bad architecture.
