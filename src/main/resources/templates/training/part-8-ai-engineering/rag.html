Retrieval-Augmented Generation

Learn how enterprise documents and knowledge are chunked, indexed, retrieved, filtered and grounded into model responses.

Learning objectives

By the end of this lesson, you should be able to

Explain the architecture

Use accurate AI terminology and place probabilistic model behavior inside normal enterprise application boundaries.

Separate AI from authority

Identify what the model may interpret or generate versus what deterministic systems must authorize and execute.

Recognize failure modes

Reason about hallucination, data exposure, tool misuse, unreliable automation, cost and operational failure.

Design a controlled implementation

Connect AI components to IAM, APIs, data, observability, testing and human governance.

Start with the engineering problem

A model's pretrained knowledge is not your organization's private, current or authoritative knowledge base.

The durable skill is not memorizing model brands. It is knowing where probabilistic AI belongs, where it does not belong, and how to surround it with mature software-engineering controls.

Commercial principle: AI should increase the capability of an enterprise system without weakening identity, authorization, data integrity, auditability or operational control.
Core concepts

Vocabulary that matters in production

Embedding
A numerical representation used to compare semantic similarity between text or other content.
Vector Search
Retrieves nearby embeddings likely to be semantically relevant to a query.
Chunking
Splits documents into retrieval-sized units while preserving enough context to remain meaningful.
Metadata Filtering
Restricts retrieval by tenant, department, document type, date, sensitivity or authorization scope.
Hybrid Search
Combines semantic retrieval with lexical/keyword ranking for better precision.
Grounded Answer
A response constrained by retrieved authoritative evidence rather than unsupported model memory.
End-to-end flow

Follow one request through the architecture

1Ingest

Collect approved documents, policies, manuals, tickets, knowledge articles or data products.

2Parse and chunk

Extract content and split it into context-preserving segments.

3Enrich metadata

Attach source, owner, access scope, dates, classifications and business identifiers.

4Embed and index

Create searchable representations in vector and/or lexical indexes.

5Retrieve

Use the user's query plus security filters to identify relevant chunks.

6Generate

Provide retrieved evidence to the LLM with instructions to answer only from supported context.

7Evaluate

Measure retrieval recall/precision, groundedness, citation correctness and answer usefulness.

Commercial scenario

Move from demo thinking to enterprise thinking

A procurement analyst asks what a supplier contract permits. The system searches only contracts the analyst may access, retrieves relevant clauses, cites them, and avoids answering beyond the retrieved evidence.

Identity
Who is asking, what organization/tenant are they in, and what are they permitted to do?
Authority
Which deterministic service owns the business fact or action?
Evidence
What logs, traces, retrieved sources, tool results and policy decisions prove what happened?
Reference application

Connect AI to the Bootcamp Spring Boot platform

Add a Bootcamp knowledge base containing order policies, return rules and product documentation. Keep transactional order state in APIs/MySQL; use RAG for document knowledge. This teaches the distinction between knowledge retrieval and live system execution.

Keycloak
Identity, authentication and trusted claims.
Spring Security
Deterministic access enforcement at application/API boundaries.
Services / APIs
Authoritative business operations exposed as governed capabilities.
MySQL
Transactional state remains in the system of record.
Production controls

What surrounds the model

IAM & policy
SSO, roles/attributes, tenant boundaries and purpose-aware authorization.
Evaluation
Representative test sets for quality, safety, groundedness and tool correctness.
Observability
Trace model calls, retrieval, tools, latency, cost, errors and decisions.
Human governance
Approval and accountability for consequential actions and exceptions.
Common failure modes

Where AI systems fail when engineering discipline is missing

Embedding everything

Low-value or unauthorized content is indexed without ownership or retention controls.

No metadata authorization

The retriever returns a relevant document the user is not entitled to see.

Bad chunk boundaries

Clauses lose headings, definitions or neighboring context needed for correct interpretation.

RAG as correctness guarantee

Retrieval can still return irrelevant, stale or contradictory material.

Hands-on lab

Apply the concept to the reference system

Design a RAG pipeline for e-commerce policy documents. Define chunking strategy, metadata fields, access filters, retrieval method, top-k behavior, citation format and three evaluation tests.

Deliverable: Produce a one-page implementation design with architecture, trust boundaries, allowed capabilities, validation, failure handling, observability and acceptance criteria.
Knowledge check

Can you defend the design?

  1. Which component owns the authoritative business fact?
  2. What can the model decide, and what must deterministic policy decide?
  3. How is user identity carried into retrieval and tool execution?
  4. What failure could produce a fluent but unsafe result?
  5. How would you test this before production?
  6. What evidence would an operator or auditor need after an incident?
Lesson recap

Five things to remember

1. RAG supplies current private knowledge.
2. Retrieval quality limits answer quality.
3. Metadata is part of security.
4. Documents and transactional APIs serve different purposes.
5. Groundedness must be measured.
Career perspective

AI-era engineers still need strong software-engineering foundations

The engineer who understands IAM, APIs, data, distributed systems, observability, testing and business workflows can use AI far more effectively than someone who knows prompting alone. The AI layer magnifies both good architecture and bad architecture.
